Arrays and Complexity Analysis

Detailed concept notes
1. What is an array?

An array is a collection of elements stored in an ordered sequence. Each element is accessed using an index. In most programming languages, the first index is 0.

Example: In [12, 25, 38, 41], the element at index 2 is 38.

2. Array operations
  • Access: Retrieve an element using its index.
  • Traversal: Visit each element one by one.
  • Insertion: Add an element at a particular position. Existing elements may need shifting.
  • Deletion: Remove an element. Remaining elements may need shifting.
  • Searching: Find the position of a required value.
  • Updating: Replace the value at an existing index.
3. Types of arrays

A one-dimensional array stores elements in a single sequence. A two-dimensional array represents rows and columns, while multidimensional arrays use additional dimensions.

A static array generally has a fixed capacity. Dynamic arrays can grow when additional capacity is required, although resizing may involve allocating a larger block and copying elements.

4. Time complexity

Time complexity describes how an algorithm's running time grows as the input size increases. It focuses on growth rather than the exact time taken on a particular computer.

  • O(1): Constant time.
  • O(log n): Logarithmic growth.
  • O(n): Linear growth.
  • O(n log n): Common in efficient comparison sorting.
  • O(n²): Quadratic growth, often seen in nested loops.
5. Understanding Big-O notation

Big-O describes an asymptotic upper bound on growth. It helps compare algorithms for large inputs. Ignore constant factors and lower-order terms when describing the dominant growth rate.

For example, 3n² + 5n + 10 has O(n²) growth because the squared term dominates for large n.

6. Best, average and worst cases

The best case describes the most favourable input, the average case describes expected behaviour under an assumed input distribution, and the worst case describes the maximum growth for inputs of a given size.

Linear search takes O(1) time in its best case when the first element matches, but O(n) in its worst case.

7. Space complexity

Space complexity measures memory usage as input size grows. Auxiliary space refers to extra memory used by an algorithm, excluding the input itself.

8. Common array searching and sorting algorithms
  • Linear search checks elements one by one and works on unsorted arrays.
  • Binary search repeatedly halves the search interval and requires sorted data.
  • Bubble sort repeatedly swaps adjacent out-of-order elements.
  • Selection sort repeatedly selects the smallest remaining element.
  • Insertion sort builds a sorted portion by inserting each new element into its correct position.
  • Merge sort divides the array, sorts the parts and merges them.
  • Quick sort partitions elements around a pivot and recursively sorts the partitions.
9. Typical complexity comparisons
  • Array indexing: O(1).
  • Linear search: O(n).
  • Binary search: O(log n), on sorted data.
  • Insertion or deletion at an arbitrary array position: O(n), due to shifting.
  • Merge sort: O(n log n) time.
  • Quick sort: O(n log n) average time and O(n²) worst-case time with unfavourable partitions.
10. Interview problem-solving approach

For an array problem, identify whether the input is sorted, whether duplicate values are allowed and whether extra memory is permitted. Consider two-pointer methods, prefix sums, hashing or binary search when appropriate.

Always explain the algorithm, its correctness and its time and space complexity.

Common mistakes
  • Confusing an array index with an element's position in ordinary counting.
  • Applying binary search to unsorted data.
  • Ignoring the cost of shifting elements.
  • Calling an algorithm O(1) merely because it uses one statement.
  • Reporting time complexity without considering the input size.
Important formulas and quick reference
  • Index access: O(1).
  • Linear search: O(n).
  • Binary search on sorted data: O(log n).
  • Full traversal: O(n).
  • Auxiliary space depends on extra storage used.
Worked example

For an array of 100 elements, how many elements may linear search inspect in the worst case?

  1. The target may be at the final position or absent.
  2. Every element may need to be checked.
  3. Worst-case checks = 100, proportional to n.

CORE

Stacks, Queues and Linked Lists

Detailed concept notes
1. Stack data structure

A stack follows the Last In, First Out (LIFO) principle. The most recently inserted element is removed first.

Think of a stack of books: the book placed on top is normally the first one removed.

2. Stack operations
  • Push: Insert an element at the top.
  • Pop: Remove the top element.
  • Peek or Top: Read the top element without removing it.
  • isEmpty: Check whether the stack contains elements.

These operations usually take O(1) time in a standard stack implementation.

3. Stack applications
  • Function calls and recursion.
  • Undo and redo operations.
  • Expression evaluation and conversion.
  • Parentheses and bracket matching.
  • Backtracking and depth-first search.
4. Queue data structure

A queue follows the First In, First Out (FIFO) principle. The earliest inserted element is removed first.

Insertion generally happens at the rear, while deletion happens at the front.

5. Queue operations
  • Enqueue: Add an element at the rear.
  • Dequeue: Remove an element from the front.
  • Front or Peek: View the first element.
  • isEmpty: Check whether the queue is empty.
6. Types of queues
  • Simple queue: Follows FIFO ordering.
  • Circular queue: Connects the last position back to the first to reuse available space.
  • Priority queue: Removes elements according to priority rather than insertion order alone.
  • Deque: Allows insertion and deletion at both ends.
7. Linked lists

A linked list consists of nodes. Each node stores data and one or more links to other nodes. Unlike an array, its nodes do not need to occupy consecutive memory locations.

  • Singly linked list: Each node points to the next node.
  • Doubly linked list: Each node points to both the previous and next nodes.
  • Circular linked list: The final node links back to an earlier node, commonly the first node.
8. Linked-list operations

Traversal visits nodes one by one. Searching checks node values. Insertion and deletion adjust links between nodes.

Inserting at the head of a singly linked list takes O(1) time. Searching for a value generally takes O(n). Accessing an arbitrary position also takes O(n), because nodes must be traversed.

9. Comparing the structures
  • Arrays provide fast indexed access but may require shifting for insertion or deletion.
  • Linked lists support flexible insertion and deletion when the relevant node or link is already known, but do not provide direct indexed access.
  • Stacks restrict access to the top element.
  • Queues process elements in arrival order unless a priority-based design is used.
10. Choosing the right structure

Use a stack for nested operations, recursion and undo behaviour. Use a queue for scheduling and waiting-line processing. Use a linked list when link-based insertion and deletion are useful and direct random access is not essential.

Common mistakes
  • Confusing LIFO with FIFO.
  • Removing a queue element from the wrong end.
  • Forgetting to update both links in a doubly linked list.
  • Assuming linked lists support O(1) access to any index.
  • Ignoring empty and single-node edge cases.
Important formulas and quick reference
  • Stack: LIFO.
  • Queue: FIFO.
  • Stack push/pop: O(1) at the top.
  • Queue enqueue/dequeue: O(1) with suitable front/rear references.
  • Linked-list search: O(n).
Worked example

Push 10, then 20, then 30 onto an empty stack. Perform one pop.

  1. Stack from bottom to top: 10, 20, 30.
  2. Pop removes the top item.
  3. Removed item = 30.

Object-Oriented Programming

Detailed concept notes
1. What is object-oriented programming?

Object-oriented programming (OOP) is a programming approach that organises software around objects. An object combines data, called attributes or fields, with behaviour, represented by methods.

A class defines the structure and behaviour that its objects can use. An object is an instance of a class.

2. Classes and objects

Consider a Student class with attributes such as name and roll number, and methods such as display_details(). Individual students are objects created from that class, each with its own data.

3. Encapsulation

Encapsulation combines data and related methods into a unit and controls how internal state is accessed or changed. It helps protect an object's valid state.

For example, a bank account can provide a deposit method that checks whether an amount is valid before updating the balance.

4. Abstraction

Abstraction exposes the essential operations of a system while hiding unnecessary implementation details. A user can operate a vehicle without needing to understand every internal mechanical process.

5. Inheritance

Inheritance allows a new class to reuse and extend the features of an existing class. The existing class is often called the parent or base class, while the new class is the child or derived class.

For example, a Vehicle class may define common properties, while Car and Motorcycle classes add their own specialised behaviour.

6. Polymorphism

Polymorphism means that a common interface can represent different underlying behaviours. For example, different classes may implement a method called calculate_area() in their own way.

Method overriding allows a child class to provide its own implementation of an inherited method. Some languages also support method overloading, where methods share a name but have different parameter lists.

7. Constructors and destructors

A constructor is used to initialise an object when it is created. In Python, __init__() is commonly used for initialisation. Destructors or cleanup mechanisms relate to releasing resources; their exact behaviour depends on the programming language.

8. Composition and aggregation

Composition models a strong whole-part relationship in which a component's lifetime is closely tied to its containing object. Aggregation represents a looser relationship where the associated objects can exist independently.

9. Access control

Access modifiers or conventions help control visibility. Common terms include public, protected and private. Their exact enforcement differs between programming languages. Python, for example, uses naming conventions rather than the same strict access enforcement found in some other languages.

10. OOP design principles
  • Single Responsibility: A class should have one clear responsibility.
  • Open/Closed: Software components should be open to extension but closed to unnecessary modification.
  • Liskov Substitution: A subtype should be usable wherever its base type is expected without breaking correctness.
  • Interface Segregation: Prefer focused interfaces over large interfaces that force unused dependencies.
  • Dependency Inversion: High-level logic should depend on abstractions rather than concrete implementation details.
11. When OOP is useful

OOP is useful when software contains related entities, reusable behaviours and complex state. It is common in application development, simulations, enterprise systems and game development.

Common interview mistakes
  • Confusing a class with an object.
  • Describing encapsulation and abstraction as identical concepts.
  • Assuming inheritance is always better than composition.
  • Confusing overriding with overloading.
  • Forgetting that language-specific OOP rules can differ.
Important formulas and quick reference
  • Class: blueprint.
  • Object: instance.
  • Encapsulation: controlled data access.
  • Abstraction: hide implementation complexity.
  • Inheritance: extend an existing class.
  • Polymorphism: common interface, varied behaviour.
Worked example

Suppose a base class Vehicle defines a method move(). A Car class inherits from Vehicle and provides its own implementation.

  1. Vehicle is the base class.
  2. Car is the derived class.
  3. Reusing and extending Vehicle demonstrates inheritance.
  4. Calling move() on different vehicle objects can demonstrate polymorphism.

CORE

DBMS and SQL

Detailed concept notes
1. Database and DBMS

A database is an organised collection of data. A Database Management System (DBMS) is software used to define, store, retrieve, update and manage that data.

A relational DBMS stores data in tables made up of rows and columns. Examples include MySQL, PostgreSQL, Oracle Database and Microsoft SQL Server.

2. Tables, rows and columns

A table represents a collection of related records. Each row represents one record, while each column represents an attribute. A schema describes the structure of the database.

3. Keys in a relational database
  • Primary key: Uniquely identifies each row and cannot contain NULL.
  • Foreign key: References a candidate or primary key in another table or the same table.
  • Candidate key: A minimal set of attributes capable of uniquely identifying a row.
  • Composite key: A key made from more than one column.
  • Alternate key: A candidate key not selected as the primary key.
4. SQL command categories
  • DDL: Defines database structures. Examples: CREATE, ALTER, DROP.
  • DML: Changes data. Examples: INSERT, UPDATE, DELETE.
  • DQL: Retrieves data. Example: SELECT.
  • DCL: Controls permissions. Examples: GRANT and REVOKE.
  • TCL: Manages transactions. Examples: COMMIT and ROLLBACK.
5. Basic SQL query structure

A SELECT query retrieves data from one or more tables. WHERE filters rows, ORDER BY sorts results, and GROUP BY forms groups for aggregate calculations.

Example: SELECT department, COUNT(*) FROM employees GROUP BY department;

This groups employees by department and counts the records in each group.

6. Joins
  • INNER JOIN returns matching rows from both tables.
  • LEFT JOIN keeps all rows from the left table and matching rows from the right.
  • RIGHT JOIN keeps all rows from the right table and matching rows from the left.
  • FULL OUTER JOIN returns matched rows and unmatched rows from both sides, where supported.
  • CROSS JOIN returns combinations of rows from both tables.
7. Aggregate functions

COUNT() counts rows or non-NULL values depending on the expression. SUM() calculates a total, AVG() calculates an average, MIN() finds the smallest value and MAX() finds the largest value.

HAVING filters groups after aggregation, while WHERE filters rows before grouping.

8. Normalisation

Normalisation organises relational tables to reduce unnecessary duplication and update anomalies.

  • First Normal Form (1NF): Each field contains an atomic value and repeating groups are avoided.
  • Second Normal Form (2NF): The table is in 1NF and non-key attributes depend on the whole candidate key, not just part of a composite key.
  • Third Normal Form (3NF): The table is in 2NF and non-key attributes do not have inappropriate transitive dependencies on candidate keys.
9. Transactions and ACID

A transaction is a logical unit of database work. ACID describes four important properties:

  • Atomicity: The transaction completes as a whole or is rolled back.
  • Consistency: A transaction preserves database rules and constraints.
  • Isolation: Concurrent transactions are controlled to avoid incorrect interference.
  • Durability: Committed changes survive failures according to the system's guarantees.
10. Indexes and query performance

An index helps a database locate records without scanning every row in many situations. Indexes can improve read performance but require storage and may add overhead to inserts, updates and deletes.

Query optimisation involves selecting efficient access paths, using appropriate indexes and examining execution plans.

11. NULL and constraints

NULL represents missing or unknown information and is not the same as zero or an empty string. SQL uses IS NULL and IS NOT NULL for NULL checks. Constraints such as NOT NULL, UNIQUE, CHECK and FOREIGN KEY help maintain valid data.

Common mistakes
  • Using WHERE to filter aggregate results instead of HAVING.
  • Assuming NULL equals zero.
  • Joining tables without understanding their relationships.
  • Confusing DELETE, DROP and TRUNCATE.
  • Creating indexes without considering write overhead.
Important formulas and quick reference
  • SELECT columns FROM table;
  • WHERE: filter rows.
  • ORDER BY: sort results.
  • GROUP BY: group rows.
  • COUNT(): count rows or non-null values.
Worked example

Retrieve employees whose salary exceeds 30000:

SELECT name, salary
FROM employees
WHERE salary > 30000;
  1. SELECT chooses the columns.
  2. FROM identifies the table.
  3. WHERE applies the condition.

CORE

Operating Systems: Processes and Memory

Detailed concept notes
1. What is an operating system?

An operating system (OS) manages computer hardware and provides services for applications. It coordinates CPU execution, memory, storage, input/output devices and user access.

2. Program and process

A program is a set of instructions stored for execution. A process is a program in execution, with its own execution state and allocated resources.

A process typically has a process identifier, program counter, CPU registers, memory information and scheduling information.

3. Process states

A simplified process model includes New, Ready, Running, Waiting or Blocked, and Terminated. A process moves between these states as it is created, scheduled, waits for events and completes.

4. Process Control Block

The Process Control Block (PCB) stores information the operating system needs to manage a process. It commonly includes process state, process ID, CPU context, scheduling information and memory-management information.

5. CPU scheduling

CPU scheduling selects a ready process for execution. Common algorithms include:

  • First Come, First Served (FCFS): Processes are handled in arrival order.
  • Shortest Job First (SJF): Selects the process with the shortest expected CPU burst.
  • Priority Scheduling: Selects according to priority.
  • Round Robin: Gives each process a time slice in turn.
6. Scheduling measurements
  • Turnaround time = Completion time − Arrival time.
  • Waiting time = Turnaround time − CPU burst time, in a simple single-burst model.
  • Response time = First CPU start time − Arrival time.

Throughput measures the number of processes completed per unit of time. Context switching occurs when the CPU changes from one process or thread to another.

7. Threads and multithreading

A thread is an execution unit within a process. Threads in the same process commonly share its address space and resources while maintaining their own execution state and stack.

Multithreading can improve responsiveness and resource utilisation, but shared data requires careful synchronisation.

8. Synchronisation and deadlocks

Critical sections access shared resources. Synchronisation mechanisms such as mutexes and semaphores help coordinate concurrent execution.

A deadlock can occur when processes wait indefinitely for resources held by one another. Four commonly discussed necessary conditions are mutual exclusion, hold and wait, no pre-emption and circular wait.

9. Memory management

The OS manages memory allocation and protection. Logical or virtual addresses are translated into physical addresses through hardware and operating-system mechanisms.

Paging divides virtual memory into fixed-size pages and physical memory into frames. Segmentation divides memory into logical regions of varying sizes.

10. Virtual memory

Virtual memory gives each process an address space that can be larger than the currently available physical memory. Pages may be loaded when required, using mechanisms such as demand paging.

A page fault occurs when a referenced page is not currently available in physical memory and the operating system must handle the access.

11. Page replacement

When memory is full, a page-replacement algorithm selects a page to remove. Common approaches include FIFO, Least Recently Used (LRU) and Optimal replacement. Optimal replacement is mainly a theoretical benchmark because it requires knowledge of future references.

12. Fragmentation

Internal fragmentation is unused space inside an allocated block. External fragmentation occurs when free memory is divided into separated regions that may not satisfy a large contiguous allocation request.

Common interview mistakes
  • Confusing a program with a process.
  • Confusing waiting time with turnaround time.
  • Assuming threads have completely separate process memory.
  • Confusing paging with segmentation.
  • Forgetting that a page fault does not always indicate an error in the program.
Important formulas and quick reference
  • Turnaround time = completion time - arrival time.
  • Waiting time = turnaround time - burst time.
  • Response time = first response time - arrival time.
  • Round robin uses a time quantum.
Worked example

A process arrives at time 0, runs for 5 units and completes at time 8.

  1. Turnaround time = 8 - 0 = 8.
  2. Burst time = 5.
  3. Waiting time = 8 - 5 = 3 units.

CORE

Computer Networks: TCP/IP and HTTP

Detailed concept notes
1. What is a computer network?

A computer network connects devices so they can exchange data and share resources. Networks may be organised as LANs, MANs or WANs according to their coverage and design.

2. Network models

The OSI model describes communication using seven conceptual layers:

  1. Physical: Transmits raw bits through a medium.
  2. Data Link: Handles local-link framing and addressing.
  3. Network: Provides logical addressing and routing.
  4. Transport: Supports end-to-end transport between applications.
  5. Session: Describes session establishment and management.
  6. Presentation: Describes data representation and transformation.
  7. Application: Provides network services to applications.

The TCP/IP model groups networking functions into Link, Internet, Transport and Application layers.

3. IP addressing

An IP address identifies an interface on an IP network. IPv4 uses 32-bit addresses, commonly written in dotted-decimal form. IPv6 uses 128-bit addresses and supports a much larger address space.

A subnet mask or prefix length identifies the network portion of an address. Routing allows packets to travel between different networks.

4. TCP and UDP

TCP is connection-oriented and provides reliable, ordered byte-stream delivery using mechanisms such as acknowledgements, retransmission and flow control.

UDP is connectionless and provides datagrams without TCP's built-in delivery and ordering guarantees. It is useful when low overhead or application-controlled transport behaviour is preferred.

5. Ports and sockets

A port number identifies an application endpoint on a host. A socket commonly combines an IP address and port with a transport protocol to identify a communication endpoint.

Commonly encountered ports include HTTP 80, HTTPS 443, DNS 53 and SSH 22. Actual services can be configured to use different ports.

6. DNS

The Domain Name System translates domain names into records such as IP addresses. It allows users and applications to use memorable names instead of manually entering numeric addresses.

7. HTTP

HTTP is an application-layer protocol used for communication between clients and servers. A request commonly includes a method, path, headers and sometimes a body. The server responds with a status code, headers and optionally a body.

  • GET: Requests a representation of a resource.
  • POST: Submits data for processing.
  • PUT: Creates or replaces a resource at a specified location, according to the API's semantics.
  • PATCH: Applies a partial modification.
  • DELETE: Requests removal of a resource.
8. HTTP status codes
  • 2xx: Successful processing, such as 200 OK and 201 Created.
  • 3xx: Redirection, such as 301 Moved Permanently.
  • 4xx: Client-side request problems, such as 400 Bad Request, 401 Unauthorized, 403 Forbidden and 404 Not Found.
  • 5xx: Server-side failures, such as 500 Internal Server Error and 503 Service Unavailable.
9. HTTPS and TLS

HTTPS is HTTP protected by TLS. TLS helps provide encryption, integrity protection and server authentication through certificates. It protects data while it travels between the communicating endpoints.

10. Network performance
  • Bandwidth: The capacity of a link to carry data.
  • Throughput: The actual rate of successful data transfer.
  • Latency: The delay experienced by data travelling through a system.
  • Packet loss: Data packets that fail to reach their destination.
  • Jitter: Variation in packet delay.
11. Common network devices

A switch forwards frames within a local network, commonly using MAC addresses. A router forwards packets between networks using IP addresses. An access point connects wireless devices to a network. A firewall applies traffic-control rules.

12. Client-server and API communication

In a client-server model, clients request services and servers respond. Web APIs commonly use HTTP methods, status codes, headers and structured data formats such as JSON.

Stateless HTTP requests do not require the server to retain the full application state of every previous request, although applications can use cookies, tokens and other mechanisms to maintain sessions.

Common interview mistakes
  • Confusing IP addresses with MAC addresses.
  • Assuming TCP and UDP provide the same guarantees.
  • Confusing bandwidth with actual throughput.
  • Thinking HTTPS and HTTP are separate application protocols with unrelated request structures.
  • Confusing HTTP status-code categories.
Important formulas and quick reference
  • HTTP: application layer.
  • TCP: reliable transport.
  • UDP: connectionless transport.
  • DNS: domain-name resolution.
  • HTTPS: HTTP protected with TLS.
Worked example

A browser needs to contact a website using its domain name.

  1. The browser or operating system checks available DNS information.
  2. A DNS lookup resolves the domain to an address.
  3. The client establishes the required transport connection.
  4. For HTTPS, TLS protects the application communication.
