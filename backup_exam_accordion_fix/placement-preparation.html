Fundamental structures, complexity and algorithmic reasoning.

FOUNDATION

Arrays and Complexity Analysis

Detailed concept notes
Array structure

An array stores elements in indexed positions. In a typical contiguous-memory array, index access is constant time.

Traversal and search

Traversal visits elements one by one. Linear search checks each element and has O(n) worst-case time. Binary search requires sorted data and repeatedly halves the search interval.

Insertion and deletion

Inserting or deleting near the beginning of an array may require shifting elements, so the operation is generally O(n).

Complexity

Big-O describes an asymptotic upper bound on growth. It helps compare algorithms as input size increases.

Important formulas and quick reference
  • Index access: O(1).
  • Linear search: O(n).
  • Binary search on sorted data: O(log n).
  • Full traversal: O(n).
  • Auxiliary space depends on extra storage used.
Worked example

For an array of 100 elements, how many elements may linear search inspect in the worst case?

  1. The target may be at the final position or absent.
  2. Every element may need to be checked.
  3. Worst-case checks = 100, proportional to n.
Topic-wise practice

Attempt the questions before revealing their solutions.

Beginner

Question 1: Array access by index is typically:

  1. A. O(1)
  2. B. O(log n)
  3. C. O(n)
  4. D. O(n²)
Reveal answer and explanation
Answer: O(1)

Direct indexing gives constant-time access.

Intermediate

Question 2: Worst-case linear search in n elements is:

  1. A. O(1)
  2. B. O(log n)
  3. C. O(n)
  4. D. O(n log n)
Reveal answer and explanation
Answer: O(n)

It may inspect every element.

Advanced

Question 3: Binary search requires the input to be:

  1. A. Random
  2. B. Sorted
  3. C. Reversed
  4. D. Unique only
Reveal answer and explanation
Answer: Sorted

The algorithm relies on ordered comparisons.

Exam

Question 4: Two nested loops each running n times usually produce:

  1. A. O(1)
  2. B. O(log n)
  3. C. O(n)
  4. D. O(n²)
Reveal answer and explanation
Answer: O(n²)

The inner loop runs n times for each of n outer iterations.

CORE

Stacks, Queues and Linked Lists

Detailed concept notes
Stack

A stack follows Last In, First Out (LIFO). Push inserts an item; pop removes the top item. It is useful for function calls, undo operations and expression evaluation.

Queue

A queue follows First In, First Out (FIFO). Enqueue inserts at the rear; dequeue removes from the front. Scheduling and buffering are common uses.

Linked list

A linked list consists of nodes containing data and links. Insertion can be efficient when the target position is already known, but accessing an arbitrary index requires traversal.

Trade-offs

Arrays offer direct indexed access. Linked lists offer flexible node insertion but require pointer traversal and extra link storage.

Important formulas and quick reference
  • Stack: LIFO.
  • Queue: FIFO.
  • Stack push/pop: O(1) at the top.
  • Queue enqueue/dequeue: O(1) with suitable front/rear references.
  • Linked-list search: O(n).
Worked example

Push 10, then 20, then 30 onto an empty stack. Perform one pop.

  1. Stack from bottom to top: 10, 20, 30.
  2. Pop removes the top item.
  3. Removed item = 30.

Object-Oriented Programming

Detailed concept notes
Class and object

A class defines a structure and behaviour; an object is an instance of that class.

Encapsulation

Encapsulation groups data with methods and controls how internal state is accessed.

Abstraction

Abstraction exposes essential behaviour while hiding implementation details.

Inheritance

Inheritance allows a derived class to reuse and extend the behaviour of a base class.

Polymorphism

Polymorphism allows a common interface to represent different underlying behaviours. Method overriding is a common example.

Important formulas and quick reference
  • Class: blueprint.
  • Object: instance.
  • Encapsulation: controlled data access.
  • Abstraction: hide implementation complexity.
  • Inheritance: extend an existing class.
  • Polymorphism: common interface, varied behaviour.
Worked example

Suppose a base class Vehicle defines a method move(). A Car class inherits from Vehicle and provides its own implementation.

  1. Vehicle is the base class.
  2. Car is the derived class.
  3. Reusing and extending Vehicle demonstrates inheritance.
  4. Calling move() on different vehicle objects can demonstrate polymorphism.

CORE

DBMS and SQL

Detailed concept notes
Database fundamentals

A database organises data for storage, retrieval and management. A relational database represents data in tables with rows and columns.

Keys

A primary key uniquely identifies each row. A foreign key references a key in another table and helps represent relationships.

SQL commands

SELECT retrieves records; INSERT adds rows; UPDATE changes values; DELETE removes rows. WHERE filters rows.

Joins

INNER JOIN returns matching rows from both tables. LEFT JOIN preserves every row from the left table and includes matching right-side values when available.

Normalisation

Normalisation organises relational data to reduce unnecessary duplication and update anomalies.

Important formulas and quick reference
  • SELECT columns FROM table;
  • WHERE: filter rows.
  • ORDER BY: sort results.
  • GROUP BY: group rows.
  • COUNT(): count rows or non-null values.
Worked example

Retrieve employees whose salary exceeds 30000:

SELECT name, salary
FROM employees
WHERE salary > 30000;
  1. SELECT chooses the columns.
  2. FROM identifies the table.
  3. WHERE applies the condition.

CORE

Operating Systems: Processes and Memory

Detailed concept notes
Process and thread

A process is a running program with its own execution context and resources. A thread is a unit of execution within a process. Threads in the same process generally share its address space.

Scheduling

CPU scheduling selects which ready process or thread receives processor time. Common algorithms include FCFS, SJF, priority scheduling and round robin.

Memory management

Virtual memory gives processes an abstraction of address space. Paging divides virtual memory into fixed-size pages and physical memory into frames.

Deadlock

Deadlock involves processes waiting indefinitely for resources. The classic necessary conditions are mutual exclusion, hold and wait, no preemption and circular wait.

Important formulas and quick reference
  • Turnaround time = completion time - arrival time.
  • Waiting time = turnaround time - burst time.
  • Response time = first response time - arrival time.
  • Round robin uses a time quantum.
Worked example

A process arrives at time 0, runs for 5 units and completes at time 8.

  1. Turnaround time = 8 - 0 = 8.
  2. Burst time = 5.
  3. Waiting time = 8 - 5 = 3 units.

CORE

Computer Networks: TCP/IP and HTTP

Detailed concept notes
Network models

Layered models divide communication into responsibilities. The TCP/IP model commonly uses link, internet, transport and application layers.

IP and MAC addresses

IP addresses identify interfaces at the network layer. MAC addresses are used for delivery on a local link.

TCP and UDP

TCP provides reliable, ordered byte-stream delivery. UDP is connectionless and has lower protocol overhead, but does not itself guarantee delivery or ordering.

HTTP and HTTPS

HTTP is an application-layer protocol used for web communication. HTTPS protects HTTP communication using TLS.

DNS

DNS translates domain names into records such as IP addresses.

Important formulas and quick reference
  • HTTP: application layer.
  • TCP: reliable transport.
  • UDP: connectionless transport.
  • DNS: domain-name resolution.
  • HTTPS: HTTP protected with TLS.
Worked example

A browser needs to contact a website using its domain name.

  1. The browser or operating system checks available DNS information.
  2. A DNS lookup resolves the domain to an address.
  3. The client establishes the required transport connection.
  4. For HTTPS, TLS protects the application communication.
