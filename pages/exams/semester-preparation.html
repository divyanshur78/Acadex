FOUNDATION

Functions, Limits and Continuity

Detailed concept notes
1. What is a function?

A function is a rule that assigns exactly one output to every permitted input. It describes a relationship between two quantities and is one of the most important ideas in mathematics, calculus and engineering.

If a function is written as f(x) = x² + 2x, then the input x is processed using the rule x² + 2x.

Example: For x = 3, f(3) = 3² + 2(3) = 15.

A function can be represented using an equation, table, graph, mapping diagram or verbal description.

2. Domain, codomain and range
  • Domain: The set of all permitted input values.
  • Codomain: The set in which the outputs are defined to lie.
  • Range: The set of actual output values produced by the function.

Example: For f(x) = x² with domain consisting of all real numbers, the range is [0, ∞), because a real square can never be negative.

How to find a domain:

  • A denominator must not be zero.
  • The expression inside an even root must be non-negative when working with real numbers.
  • The argument of a real logarithm must be positive.
  • Check all restrictions together when an expression contains more than one operation.

Worked example: Find the domain of f(x) = 1/(x − 4).

The denominator cannot equal zero. Therefore x − 4 ≠ 0, so x ≠ 4. The domain is all real numbers except 4.

3. Types of functions
  • Constant: f(x) = c. The output remains fixed.
  • Identity: f(x) = x. The output equals the input.
  • Linear: f(x) = mx + c. Its graph is a straight line.
  • Quadratic: f(x) = ax² + bx + c, where a ≠ 0. Its graph is a parabola.
  • Polynomial: A finite sum of non-negative integer powers of x with constant coefficients.
  • Rational: A ratio of two polynomials, wherever the denominator is non-zero.
  • Modulus: f(x) = |x|, which measures distance from zero.
  • Exponential: f(x) = aˣ, where a is positive and not equal to 1.
  • Logarithmic: f(x) = logₐx, defined for x > 0 when a is positive and not equal to 1.
  • Trigonometric: Functions such as sin x, cos x and tan x.
4. Even, odd and periodic functions

An even function satisfies f(−x) = f(x). Its graph is symmetric about the y-axis. For example, f(x) = x².

An odd function satisfies f(−x) = −f(x). Its graph has symmetry about the origin. For example, f(x) = x³.

A periodic function repeats its values after a fixed interval T. It satisfies f(x + T) = f(x), where T is a positive period. The basic sine and cosine functions have period 2π when measured in radians.

These properties are especially useful in calculus and definite-integral problems.

5. Composition of functions

Function composition means applying one function to the output of another. The composition of f and g is written as (f ∘ g)(x) = f(g(x)).

Worked example: Let f(x) = x² and g(x) = x + 3.

Then f(g(x)) = (x + 3)² = x² + 6x + 9.

Order matters: g(f(x)) = x² + 3, which is generally different.

6. Understanding a limit

A limit describes the value that a function approaches as its input gets closer to a particular number. The function does not necessarily need to be defined at that exact number for the limit to exist.

limₓ→ₐ f(x) = L

This means that f(x) approaches L as x approaches a.

Example: For f(x) = x + 4, as x approaches 2, the output approaches 6.

limₓ→₂ (x + 4) = 6.

7. Left-hand and right-hand limits

The left-hand limit examines values approaching a from below, while the right-hand limit examines values approaching a from above.

LHL = limₓ→ₐ⁻ f(x)

RHL = limₓ→ₐ⁺ f(x)

A two-sided limit exists only when both one-sided limits exist and are equal.

Example: If the left-hand limit is 5 and the right-hand limit is 5, the two-sided limit is 5. If they are different, the two-sided limit does not exist.

8. Methods for evaluating limits
  • Direct substitution: Substitute the approaching value when the expression is continuous there.
  • Factorisation: Factor the numerator and denominator, then simplify common factors.
  • Rationalisation: Multiply by a suitable conjugate to simplify expressions involving roots.
  • Standard limits: Recognise common trigonometric, exponential and logarithmic forms.
  • Algebraic simplification: Rearrange the expression before substituting.

Worked example: Evaluate limₓ→₃ (x² − 9)/(x − 3).

  1. Direct substitution produces 0/0, an indeterminate form.
  2. Factorise: x² − 9 = (x − 3)(x + 3).
  3. For x ≠ 3, cancel the common factor.
  4. The expression becomes x + 3.
  5. The limit is 3 + 3 = 6.
9. Important standard limits
  • limₓ→₀ (sin x)/x = 1, when x is measured in radians.
  • limₓ→₀ (tan x)/x = 1, when x is measured in radians.
  • limₓ→₀ (1 − cos x)/x² = 1/2.
  • limₓ→₀ [(1 + x)ⁿ − 1]/x = n, for a fixed real n.
  • limₓ→₀ (eˣ − 1)/x = 1.

Memorise the conditions as well as the formulas. For example, the standard trigonometric limits use radians, not degrees.

10. Continuity of a function

A function is continuous at x = a when its value exists there, its limit exists there, and the limit equals the actual function value.

limₓ→ₐ f(x) = f(a)

Equivalently, all three conditions must hold:

  1. f(a) is defined.
  2. limₓ→ₐ f(x) exists.
  3. limₓ→ₐ f(x) = f(a).

Example: f(x) = x² is continuous at x = 2 because the limit and function value are both 4.

11. Types of discontinuity
  • Removable: The limit exists, but the function value is missing or different. It may be repaired by defining the function appropriately at that point.
  • Jump: The left-hand and right-hand limits exist but are unequal.
  • Infinite: The function grows without bound near the point, as can happen near a vertical asymptote.

Always examine the one-sided limits and the actual function value before deciding whether a function is continuous.

12. Continuity of common functions

Polynomials are continuous for every real input. Rational functions are continuous wherever their denominators are non-zero. Exponential functions are continuous for all real inputs. Logarithmic functions are continuous on their domains. Trigonometric functions are continuous wherever they are defined.

13. Advanced problem-solving approach

For a piecewise-defined function, check continuity at the points where its formula changes. Calculate the left-hand limit, right-hand limit and function value separately. For a limit involving 0/0, do not conclude that the limit is zero or does not exist; simplify the expression or use an appropriate limit method first.

14. Common mistakes
  • Confusing the domain with the range.
  • Assuming a limit must equal the function value.
  • Substituting into an expression before checking for an indeterminate form.
  • Checking only one side of a two-sided limit.
  • Forgetting that standard trigonometric limits use radians.
  • Assuming every function with a graph has a limit at every point.
Important formulas and quick reference
  • For a polynomial, lim x→a f(x) = f(a).
  • Continuity at a: lim x→a f(x) = f(a).
  • For a product: lim(fg) = (lim f)(lim g), when the limits exist.
Worked example

Evaluate lim x→2 (x² + 3x).

  1. Substitute x = 2 because the expression is a polynomial.
  2. 2² + 3(2) = 4 + 6.
  3. The limit is 10.

CORE CONCEPT

Differentiation and Applications

Detailed concept notes
1. Meaning of differentiation

Differentiation measures how quickly a function changes with respect to its input. If a function represents position over time, its derivative represents velocity. If it represents the height of a curve, its derivative describes the slope of the curve.

The derivative is written as f′(x), dy/dx or d/dx[f(x)].

Geometrically, the derivative at a point is the slope of the tangent to the curve at that point.

2. Derivative from first principles

The derivative is defined using the limit of the average rate of change as the interval becomes very small.

f′(x) = limₕ→₀ [f(x + h) − f(x)]/h

This definition is called differentiation from first principles.

Worked example: Find the derivative of f(x) = x².

  1. f(x + h) = (x + h)² = x² + 2xh + h².
  2. Subtract f(x): 2xh + h².
  3. Divide by h: 2x + h.
  4. Take the limit as h approaches zero.
  5. Therefore f′(x) = 2x.
3. Basic differentiation rules
  • Constant rule: The derivative of a constant is zero.
  • Power rule: d(xⁿ)/dx = nxⁿ⁻¹.
  • Constant multiple rule: d[cf(x)]/dx = cf′(x).
  • Sum rule: d[f(x) + g(x)]/dx = f′(x) + g′(x).
  • Difference rule: d[f(x) − g(x)]/dx = f′(x) − g′(x).

Worked example: Differentiate y = 5x⁴ − 3x² + 7x − 9.

Applying the power rule term by term gives dy/dx = 20x³ − 6x + 7.

4. Product rule

Use the product rule when two differentiable functions are multiplied.

d(uv)/dx = u′v + uv′

Worked example: Differentiate y = x² sin x.

  1. Let u = x² and v = sin x.
  2. Then u′ = 2x and v′ = cos x.
  3. Apply the product rule.
  4. dy/dx = 2x sin x + x² cos x.
5. Quotient rule

Use the quotient rule when one differentiable function is divided by another, provided the denominator is non-zero.

d(u/v)/dx = (v u′ − u v′)/v²

Worked example: Differentiate y = x/(x + 1).

  1. Let u = x and v = x + 1.
  2. Then u′ = 1 and v′ = 1.
  3. Apply the quotient rule.
  4. dy/dx = [(x + 1) − x]/(x + 1)².
  5. Therefore dy/dx = 1/(x + 1)².
6. Chain rule

The chain rule differentiates a composite function: a function inside another function.

d[f(g(x))]/dx = f′(g(x)) × g′(x)

In simple terms, differentiate the outer function while keeping the inner expression, then multiply by the derivative of the inner expression.

Worked example: Differentiate y = (x² + 1)³.

  1. Outer function is the cube; inner function is x² + 1.
  2. Differentiate the outer function: 3(x² + 1)².
  3. Differentiate the inner function: 2x.
  4. Multiply: dy/dx = 6x(x² + 1)².
7. Derivatives of common functions
  • d(eˣ)/dx = eˣ.
  • d(aˣ)/dx = aˣ ln a.
  • d(ln x)/dx = 1/x, for x > 0.
  • d(sin x)/dx = cos x.
  • d(cos x)/dx = −sin x.
  • d(tan x)/dx = sec² x, wherever defined.
  • d(sin⁻¹ x)/dx = 1/√(1 − x²), for −1 < x < 1.
  • d(cos⁻¹ x)/dx = −1/√(1 − x²), for −1 < x < 1.
  • d(tan⁻¹ x)/dx = 1/(1 + x²).

These formulas assume angles are measured in radians.

8. Implicit differentiation

Sometimes x and y are related by an equation rather than y being written explicitly as a function of x. In such cases, differentiate both sides with respect to x, treating y as a function of x.

Whenever a term involving y is differentiated, apply the chain rule and multiply by dy/dx.

Worked example: x² + y² = 25.

  1. Differentiate: 2x + 2y(dy/dx) = 0.
  2. Rearrange: 2y(dy/dx) = −2x.
  3. Therefore dy/dx = −x/y, where y ≠ 0.
9. Second and higher derivatives

The derivative of a derivative is called the second derivative. It is written as f′′(x) or d²y/dx².

The first derivative describes the rate of change. The second derivative describes how that rate changes. In motion, the second derivative of position with respect to time is acceleration.

Example: If y = x³, then y′ = 3x² and y′′ = 6x.

10. Tangent and normal to a curve

The derivative at a point gives the slope of the tangent line. If the tangent slope is m, its equation through (x₁, y₁) is:

y − y₁ = m(x − x₁)

When m is non-zero, the normal is perpendicular to the tangent and has slope −1/m.

Worked example: Find the tangent to y = x² at x = 2.

  1. Differentiate: dy/dx = 2x.
  2. At x = 2, the slope is 4.
  3. The point is (2, 4).
  4. Use the point-slope equation: y − 4 = 4(x − 2).
  5. Therefore y = 4x − 4.
11. Increasing and decreasing functions

On an interval where f′(x) is positive, the function is increasing. Where f′(x) is negative, it is decreasing.

To study the behaviour of a function, find its derivative, identify where the derivative is zero or undefined, and examine the sign of the derivative in the resulting intervals.

12. Stationary points and critical points

A stationary point is a point where the first derivative equals zero. A critical point is a point in the domain where the derivative is zero or does not exist.

Not every stationary point is a maximum or minimum. For example, a stationary point can also be a point of inflection.

13. Maxima and minima

A local maximum is a point where the function is greater than or equal to nearby function values. A local minimum is a point where it is less than or equal to nearby values.

The first derivative test checks whether the derivative changes sign around a stationary point.

  • Positive to negative: local maximum.
  • Negative to positive: local minimum.
  • No sign change: neither a maximum nor a minimum by this test.

The second derivative test can also help. If f′(a) = 0 and f′′(a) is positive, the point is a local minimum. If f′′(a) is negative, it is a local maximum. If f′′(a) = 0, the test is inconclusive.

Worked example: Find the stationary point of f(x) = x² − 4x + 3.

  1. f′(x) = 2x − 4.
  2. Set the derivative to zero: 2x − 4 = 0, so x = 2.
  3. f(2) = 4 − 8 + 3 = −1.
  4. f′′(x) = 2, which is positive.
  5. Therefore (2, −1) is a local minimum.
14. Applications of differentiation
  • Motion: Velocity is the derivative of position; acceleration is the derivative of velocity.
  • Optimisation: Find maximum profit, minimum cost or shortest distance.
  • Engineering: Study changing signals, system responses and physical quantities.
  • Economics: Marginal cost and marginal revenue are derivatives of total cost and revenue.
  • Graph analysis: Determine slopes, stationary points and intervals of increase or decrease.
15. Common mistakes and tougher questions
  • Forgetting to differentiate the inner function in the chain rule.
  • Using the product rule as if it were the derivative of each factor multiplied together.
  • Applying the quotient rule in the wrong order.
  • Assuming every point where f′(x) = 0 is a maximum or minimum.
  • Ignoring points where the derivative is undefined.
  • Forgetting the restrictions on logarithmic and trigonometric derivatives.

For a difficult problem, first identify the structure: product, quotient, composition or implicit relationship. Simplify only when it helps, apply the correct rule carefully, and verify the result where possible.

Important formulas and quick reference
  • d(xⁿ)/dx = nxⁿ⁻¹
  • d(c)/dx = 0
  • d(u + v)/dx = u' + v'
  • d(uv)/dx = u'v + uv'
  • d(f(g(x)))/dx = f'(g(x))g'(x)
Worked example

Differentiate y = 3x⁴ - 2x² + 5.

  1. Differentiate each term separately.
  2. 3 × 4x³ - 2 × 2x.
  3. Therefore dy/dx = 12x³ - 4x.

Chapter 1: Matrices, Determinants and Systems of Linear Equations

Matrix fundamentals

A matrix is a rectangular arrangement of numbers or other mathematical elements in rows and columns. The order of a matrix is written as m × n, where m is the number of rows and n is the number of columns.

Common types include row matrices, column matrices, square matrices, zero matrices, diagonal matrices, identity matrices, symmetric matrices and skew-symmetric matrices.

Matrix operations

  • Addition and subtraction require matrices of the same order.
  • Scalar multiplication multiplies every entry by a scalar.
  • Matrix multiplication is possible when the columns of the first matrix equal the rows of the second.
  • Matrix multiplication is generally not commutative: AB ≠ BA.
  • The transpose interchanges rows and columns.

Determinants

For a 2 × 2 matrix:

\(A=\begin{bmatrix}a&b\\c&d\end{bmatrix}\)

\(\det(A)=ad-bc\)

A determinant is defined for square matrices. A non-zero determinant indicates that the matrix is invertible.

Inverse of a matrix

For a 2 × 2 matrix with ad − bc ≠ 0:

\(A^{-1}=\frac{1}{ad-bc}\begin{bmatrix}d&-b\\-c&a\end{bmatrix}\)

The inverse satisfies AA⁻¹ = A⁻¹A = I.

Rank and linear systems

A system of linear equations can be represented as Ax = b. The rank is the maximum number of linearly independent rows or columns.

A system is consistent when rank(A) = rank([A | b]). If the common rank equals the number of unknowns, the solution is unique.

Worked example — Easy

Question: Find the determinant of:

\(A=\begin{bmatrix}3&2\\1&4\end{bmatrix}\)

Solution: det(A) = 3 × 4 − 2 × 1 = 10.

Worked example — Moderate

Question: Solve 2x + y = 5 and x + y = 3.

Subtract the second equation from the first: x = 2. Substitute into x + y = 3 to obtain y = 1.

Practice questions

  1. Find the determinant of [[5, 2], [3, 4]].
  2. What is the order of a matrix containing 3 rows and 4 columns?
  3. When does a square matrix have an inverse?
  4. State the consistency condition for a system Ax = b.
Reveal answers

1. 14. 2. 3 × 4. 3. When its determinant is non-zero. 4. rank(A) = rank([A | b]).

Chapter 2: Differential Calculus and Applications

Meaning of differentiation

Differentiation measures the instantaneous rate of change of a function. Geometrically, the derivative represents the slope of the tangent to the curve at a point.

\(f'(x)=\lim_{h\to0}\frac{f(x+h)-f(x)}{h}\)

Basic differentiation rules

  • Constant rule: \(\frac{d}{dx}(c)=0\).
  • Power rule: \(\frac{d}{dx}(x^n)=nx^{n-1}\).
  • Sum rule: \((u+v)'=u'+v'\).
  • Product rule: \((uv)'=u'v+uv'\).
  • Quotient rule: \((u/v)'=(u'v-uv')/v^2\), where v ≠ 0.
  • Chain rule: \(\frac{d}{dx}f(g(x))=f'(g(x))g'(x)\).

Important standard derivatives

\(\frac{d}{dx}(\sin x)=\cos x\)

\(\frac{d}{dx}(\cos x)=-\sin x\)

\(\frac{d}{dx}(e^x)=e^x\)

\(\frac{d}{dx}(\ln x)=\frac{1}{x},\quad x>0\)

Higher-order derivatives

The second derivative is obtained by differentiating the first derivative. It describes how the rate of change itself changes and is used to study curvature and local extrema.

Maxima and minima

A stationary point satisfies f'(x) = 0. For a differentiable function at an interior stationary point:

  • If f''(x) is positive, the point is a strict local minimum.
  • If f''(x) is negative, the point is a strict local maximum.
  • If f''(x) is zero, the test is inconclusive.

Applications

Differentiation is used in velocity and acceleration calculations, optimisation, marginal cost, marginal revenue, error analysis and engineering models.

Worked example — Easy

Question: Differentiate f(x) = 5x³ − 2x² + 7.

Solution: f'(x) = 15x² − 4x.

Worked example — Moderate

Question: Find the stationary point of f(x) = x² − 8x + 12.

f'(x) = 2x − 8. Set it to zero: x = 4. Since f''(x) = 2, the point is a local minimum. Its value is −4.

Practice questions

  1. Differentiate 7x⁴.
  2. Differentiate sin x + cos x.
  3. State the product rule.
  4. Find the stationary point of x² − 10x + 9.
Reveal answers

1. 28x³. 2. cos x − sin x. 3. (uv)' = u'v + uv'. 4. x = 5, a minimum.

Chapter 3: Integral Calculus and Applications

Meaning of integration

Integration is used to find antiderivatives and accumulated quantities. An indefinite integral represents a family of antiderivatives.

\(\int f(x)\,dx=F(x)+C\)

Here F'(x) = f(x), and C is the constant of integration.

Basic integration rules

  • \(\int x^n\,dx=\frac{x^{n+1}}{n+1}+C,\quad n\ne-1\)
  • \(\int \frac{1}{x}\,dx=\ln|x|+C\)
  • \(\int e^x\,dx=e^x+C\)
  • \(\int \cos x\,dx=\sin x+C\)
  • \(\int \sin x\,dx=-\cos x+C\)

Methods of integration

Substitution: Replace an inner expression with a new variable to simplify the integral.

Integration by parts:

\(\int u\,dv=uv-\int v\,du\)

Partial fractions: Decompose a suitable rational expression into simpler fractions before integration.

Definite integration

A definite integral has specified limits:

Chapter 4: Differential Equations

Definition

A differential equation contains an unknown function and one or more of its derivatives. It describes relationships involving changing quantities.

Order and degree

The order is the highest derivative present. The degree is the power of the highest-order derivative after the equation has been expressed as a polynomial in derivatives, where this is possible.

First-order differential equations

A first-order equation contains only the first derivative as its highest derivative.

A separable equation can be written as:

\(\frac{dy}{dx}=g(x)h(y)\)

Separating variables gives:

\(\frac{1}{h(y)}\,dy=g(x)\,dx\)

Linear first-order equations

The standard form is:

\(\frac{dy}{dx}+P(x)y=Q(x)\)

The integrating factor is:

\(IF=e^{\int P(x)\,dx}\)

Multiplying the equation by the integrating factor allows the left side to be written as a product derivative.

Second-order linear equations

A common constant-coefficient form is:

\(ay''+by'+cy=0\)

Its characteristic equation is ar² + br + c = 0. The roots determine the form of the complementary solution.

Applications

Differential equations model population growth, cooling, electrical circuits, mechanical vibration, fluid flow and many other engineering systems.

Chapter 5: Probability and Descriptive Statistics

Probability fundamentals

Probability measures uncertainty and takes values from 0 to 1. The sample space contains all possible outcomes, while an event is a subset of those outcomes.

\(P(A\cup B)=P(A)+P(B)-P(A\cap B)\)

Conditional probability

\(P(A\mid B)=\frac{P(A\cap B)}{P(B)},\quad P(B)>0\)

For independent events, P(A ∩ B) = P(A)P(B).

Measures of central tendency

  • Mean: Sum of observations divided by the number of observations.
  • Median: Middle value after arranging observations in order.
  • Mode: Most frequently occurring value.

Measures of dispersion

Range measures the difference between maximum and minimum values. Variance measures average squared deviation from the mean, and standard deviation is its square root.

\(\sigma^2=\frac{1}{N}\sum_{i=1}^{N}(x_i-\mu)^2\)

Common distributions

  • Bernoulli: A single binary trial.
  • Binomial: Number of successes in a fixed number of independent trials.
  • Poisson: Counts occurring over a specified interval under suitable assumptions.
  • Normal: A symmetric continuous distribution described by its mean and variance.

Chapter 6: Complex Numbers and Their Applications

Introduction

A complex number contains a real part and an imaginary part. It is written as z = a + ib, where a and b are real numbers and i is the imaginary unit.

\(i^2=-1,\quad i^3=-i,\quad i^4=1\)

Real and imaginary parts

For z = a + ib, the real part is Re(z) = a and the imaginary part is Im(z) = b.

Arithmetic operations

  • Addition: (a + ib) + (c + id) = (a + c) + i(b + d).
  • Subtraction: (a + ib) − (c + id) = (a − c) + i(b − d).
  • Multiplication: (a + ib)(c + id) = (ac − bd) + i(ad + bc).

Conjugate and modulus

The conjugate of z = a + ib is z̄ = a − ib.

The modulus is:

\(|z|=\sqrt{a^2+b^2}\)

An important identity is z z̄ = |z|².

Polar representation

A non-zero complex number can be represented using its modulus r and argument θ:

\(z=r(\cos\theta+i\sin\theta)\)

Here r = |z| and θ is the angle measured from the positive real axis, with the correct quadrant considered.

Applications

Complex numbers are used in electrical engineering, alternating-current circuit analysis, signal processing, control systems and the representation of oscillations.

Chapter 7: Sequences, Series and Convergence

Sequences

A sequence is an ordered list of terms following a rule. Each term is represented by aₙ, where n indicates its position.

Arithmetic progression

An arithmetic progression (AP) has a constant difference d between consecutive terms.

\(a_n=a+(n-1)d\)

The sum of the first n terms is:

\(S_n=\frac{n}{2}[2a+(n-1)d]\)

Geometric progression

A geometric progression (GP) has a constant common ratio r between consecutive terms.

\(a_n=ar^{n-1}\)

For r ≠ 1, the sum of the first n terms is:

\(S_n=a\frac{1-r^n}{1-r}\)

When |r| < 1, the infinite geometric series converges to:

\(S_\infty=\frac{a}{1-r}\)

Limits of sequences

A sequence converges if its terms approach a finite value as n becomes very large. Otherwise, it may diverge or fail to have a limit.

Infinite series

An infinite series is the sum of the terms of an infinite sequence. Convergence is determined by the behaviour of its partial sums.

Common convergence tests

  • nth-term test: If the terms do not approach zero, the series diverges.
  • Ratio test: Examines the limiting ratio of consecutive absolute terms.
  • Comparison test: Compares a positive-term series with a known series.
  • Integral test: Relates a suitable positive decreasing series to an improper integral.

For the ratio test, let \(L=\lim_{n\to\infty}|a_{n+1}/a_n|\). If L < 1, the series converges absolutely; if L > 1, it diverges. If L = 1, the test is inconclusive.

Question: Find the 10th term of the AP 3, 7, 11, 15, ...

Solution: a = 3, d = 4. Therefore a₁₀ = 3 + 9 × 4 = 39.

Worked example — Moderate

Solution: a = 8 and r = 1/2. Since |r| < 1, the series converges. Its sum is 8/(1 − 1/2) = 16.

Chapter 8: Vector Calculus

Scalars and vectors

A scalar has magnitude only, while a vector has both magnitude and direction. Position, velocity, force and acceleration are common vector quantities.

Vector representation

A three-dimensional vector can be written as:

\(\vec A=A_x\hat i+A_y\hat j+A_z\hat k\)

Its magnitude is:

\(|\vec A|=\sqrt{A_x^2+A_y^2+A_z^2}\)

Dot product

\(\vec A\cdot\vec B=|\vec A||\vec B|\cos\theta\)

The dot product produces a scalar. It is useful for calculating work and finding the angle between vectors.

Cross product

\(|\vec A\times\vec B|=|\vec A||\vec B|\sin\theta\)

The cross product produces a vector perpendicular to both input vectors, with direction determined by the right-hand rule.

Scalar and vector fields

A scalar field assigns a scalar value to each point in space. A vector field assigns a vector to each point.

Gradient

For a scalar field φ(x, y, z):

\(\nabla\phi=\frac{\partial\phi}{\partial x}\hat i+\frac{\partial\phi}{\partial y}\hat j+\frac{\partial\phi}{\partial z}\hat k\)

The gradient points in the direction of the greatest local increase of the scalar field.

Divergence and curl

Divergence measures the local outward spreading of a vector field:

\(\nabla\cdot\vec A=\frac{\partial A_x}{\partial x}+\frac{\partial A_y}{\partial y}+\frac{\partial A_z}{\partial z}\)

Curl measures local rotational behaviour:

\(\nabla\times\vec A\)

Chapter 9: Laplace Transforms

Introduction

The Laplace transform converts a suitable function of time into a function of a complex variable s. It is widely used to solve differential equations and analyse linear systems.

\(\mathcal L\{f(t)\}=F(s)=\int_0^\infty e^{-st}f(t)\,dt\)

Standard transforms

  • \(\mathcal L\{1\}=\frac{1}{s}\)
  • \(\mathcal L\{t\}=\frac{1}{s^2}\)
  • \(\mathcal L\{t^n\}=\frac{n!}{s^{n+1}}\)
  • \(\mathcal L\{e^{at}\}=\frac{1}{s-a}\), for a suitable region of convergence.
  • \(\mathcal L\{\sin at\}=\frac{a}{s^2+a^2}\)
  • \(\mathcal L\{\cos at\}=\frac{s}{s^2+a^2}\)

Linearity property

\(\mathcal L\{af(t)+bg(t)\}=aF(s)+bG(s)\)

Transforms of derivatives

\(\mathcal L\{f'(t)\}=sF(s)-f(0)\)

\(\mathcal L\{f''(t)\}=s^2F(s)-sf(0)-f'(0)\)

These properties allow initial conditions to be included directly when transforming differential equations.

Inverse Laplace transform

The inverse transform converts F(s) back into f(t). Partial fractions are often used when F(s) is a rational expression.

Worked example — Easy

Question: Find the Laplace transform of 5.

Solution: By linearity and the transform of 1, the result is 5/s.

Worked example — Moderate

Question: Find the transform of 3t².

Solution: Since L{t²} = 2/s³, L{3t²} = 6/s³.

Applications

Applications include circuit analysis, control engineering, system response, vibration models and differential equations with initial conditions.

Chapter 10: Fourier Series and Periodic Functions

Periodic functions

A function is periodic if its values repeat after a fixed positive interval T:

\(f(x+T)=f(x)\)

The smallest positive period is called the fundamental period.

Fourier series

A suitable periodic function can be represented using a combination of sine and cosine terms:

\(f(x)=\frac{a_0}{2}+\sum_{n=1}^{\infty}(a_n\cos nx+b_n\sin nx)\)

For a function with period 2π, the coefficients are:

\(a_0=\frac{1}{\pi}\int_{-\pi}^{\pi}f(x)\,dx\)

\(a_n=\frac{1}{\pi}\int_{-\pi}^{\pi}f(x)\cos nx\,dx\)

\(b_n=\frac{1}{\pi}\int_{-\pi}^{\pi}f(x)\sin nx\,dx\)

Even and odd functions

  • Even function: f(−x) = f(x). Its Fourier series contains cosine terms and may contain a constant term.
  • Odd function: f(−x) = −f(x). Its Fourier series contains sine terms.

Harmonics

The fundamental frequency is the lowest frequency in a periodic signal. Higher integer multiples are called harmonics.

Applications

Fourier series are used in signal processing, vibration analysis, heat transfer, electrical engineering and the study of periodic systems.

Worked example — Easy

Solution: f(−x) = (−x)² = x² = f(x), so it is even.

Solution: f(−x) = −x³ = −f(x), so it is odd.

Chapter 1: Propositional Logic and Mathematical Reasoning

Propositions

A proposition is a declarative statement that has exactly one truth value: true or false. Questions and commands are not propositions.

Logical connectives

  • Negation: ¬p means not p.
  • Conjunction: p ∧ q is true only when both statements are true.
  • Disjunction: p ∨ q is true when at least one statement is true.
  • Implication: p → q is false only when p is true and q is false.
  • Biconditional: p ↔ q is true when both statements have the same truth value.

Truth tables

A truth table lists the result of a logical expression for every possible combination of input truth values. With n independent propositions, there are 2ⁿ possible rows.

Logical equivalence

Two expressions are logically equivalent if they have identical truth values in every possible case.

Important identities:

¬(p ∧ q) ≡ ¬p ∨ ¬q

¬(p ∨ q) ≡ ¬p ∧ ¬q

p → q ≡ ¬p ∨ q

Predicates and quantifiers

A predicate contains a variable and becomes a proposition when a value is assigned. The universal quantifier ∀ means "for all", while the existential quantifier ∃ means "there exists".

Methods of proof

  • Direct proof: Start from assumptions and derive the conclusion.
  • Contrapositive: Prove ¬q → ¬p instead of p → q.
  • Contradiction: Assume the opposite of the desired result and derive a contradiction.
  • Mathematical induction: Prove a base case and then prove that one case implies the next.

Worked example

Question: If p is true and q is false, evaluate p → q.

Solution: An implication is false only when its first statement is true and its second statement is false. Therefore, the result is false.

  2. What is the negation of p ∧ q according to De Morgan's law?
  3. When is p → q false?
  4. Which proof method uses a base case and an inductive step?
Reveal answers

1. 8. 2. ¬p ∨ ¬q. 3. When p is true and q is false. 4. Mathematical induction.

Chapter 2: Sets, Relations and Functions

Set theory

A set is a well-defined collection of distinct objects. Objects in a set are called elements.

Common operations include union A ∪ B, intersection A ∩ B, difference A − B and complement Aᶜ.

Important set identities

Commutative: A ∪ B = B ∪ A.

Associative: (A ∪ B) ∪ C = A ∪ (B ∪ C).

Distributive: A ∩ (B ∪ C) = (A ∩ B) ∪ (A ∩ C).

De Morgan's law: (A ∪ B)ᶜ = Aᶜ ∩ Bᶜ.

Power sets

The power set P(A) contains every subset of A, including the empty set and A itself. If a set has n elements, its power set contains 2ⁿ subsets.

Relations

A relation from A to B is a subset of the Cartesian product A × B.

  • Reflexive: Every element is related to itself.
  • Symmetric: If a is related to b, then b is related to a.
  • Antisymmetric: If a is related to b and b to a, then a = b.
  • Transitive: If a is related to b and b to c, then a is related to c.

An equivalence relation is reflexive, symmetric and transitive. A partial order is reflexive, antisymmetric and transitive.

Functions

A function assigns exactly one output to each element of its domain.

  • Injective: Different inputs produce different outputs.
  • Surjective: Every element of the codomain is reached.
  • Bijective: Both injective and surjective.

Worked example

Question: A set contains four elements. How many subsets does it have?

Solution: 2⁴ = 16 subsets.

Worked example — Moderate

Question: Is the relation "is less than or equal to" on integers a partial order?

Solution: Yes. It is reflexive, antisymmetric and transitive.

Chapter 3: Counting, Permutations and Combinations

Fundamental counting principles

If one task can be performed in m ways and another independent task in n ways, the combined tasks can be performed in mn ways. When choosing between separate alternatives, the addition principle is used.

Factorials

For a non-negative integer n:

\(n!=n(n-1)(n-2)\cdots2\cdot1,\quad 0!=1\)

Permutations

A permutation is an arrangement in which order matters.

\({}^nP_r=\frac{n!}{(n-r)!}\)

Combinations

A combination is a selection in which order does not matter.

\({}^nC_r=\frac{n!}{r!(n-r)!}\)

Binomial theorem

\((x+y)^n=\sum_{r=0}^{n}{}^nC_r x^{n-r}y^r\)

The binomial coefficient determines the numerical multiplier of each term.

Pigeonhole principle

If more objects are placed into fewer containers, at least one container must contain more than one object. The general principle also gives lower bounds on how many objects must share a container.

Chapter 4: Graph Theory and Trees

Graph fundamentals

A graph G = (V, E) consists of a set of vertices V and a set of edges E connecting pairs of vertices.

  • Undirected graph: Edges have no direction.
  • Directed graph: Edges have a direction.
  • Weighted graph: Edges carry numerical weights.
  • Simple graph: Has no self-loops or multiple edges between the same pair of vertices.

Degree of a vertex

The degree of a vertex is the number of incident edges. In an undirected graph:

\(\sum_{v\in V}\deg(v)=2|E|\)

This is known as the handshaking lemma.

Paths and cycles

A path is a sequence of connected vertices. A cycle is a path that starts and ends at the same vertex without repeating other vertices.

Connected graphs

An undirected graph is connected if a path exists between every pair of vertices.

Trees

A tree is a connected, acyclic undirected graph. A tree with n vertices has exactly n − 1 edges.

  • Rooted tree: One vertex is designated as the root.
  • Leaf: A vertex with no children in a rooted tree.
  • Binary tree: Each node has at most two children.
  • Spanning tree: A tree containing every vertex of a connected graph.

Graph representations

An adjacency matrix stores whether pairs of vertices are connected. An adjacency list stores the neighbours of each vertex. Lists are often more space-efficient for sparse graphs.

1. What is Python?

Python is a high-level, general-purpose programming language known for readable syntax. It is widely used in automation, web development, data analysis, artificial intelligence, scientific computing and software development.

Python programs are commonly executed by an interpreter. The language supports procedural, object-oriented and functional programming styles.

2. Variables and assignment

A variable is a name that refers to an object or value. In Python, a variable is created when a value is assigned to it.

name = "Aarav"
age = 19
score = 87.5

The assignment operator = stores a reference to the value on its right under the name on its left. It is not the same as the equality comparison operator ==.

Python naming rules:

  • A name may contain letters, digits and underscores.
  • A name cannot begin with a digit.
  • Python keywords cannot be used as variable names.
  • Names are case-sensitive: marks and Marks are different names.
  • Descriptive names make programs easier to understand.
3. Python data types
  • int: Whole numbers, such as 10 and −4.
  • float: Decimal numbers, such as 3.14.
  • complex: Complex numbers, such as 2 + 3j.
  • str: Text, such as "Hello".
  • bool: Boolean values True and False.
  • list: Ordered, mutable collection, such as [1, 2, 3].
  • tuple: Ordered, immutable collection, such as (1, 2, 3).
  • set: Collection of distinct elements, such as {1, 2, 3}.
  • dict: Collection of key-value pairs, such as {"name": "Aarav"}.
  • NoneType: The type of the special value None, used to represent the absence of a value.

Python is dynamically typed: a name can be assigned values of different types at different points in a program.

Example:

value = 10
print(type(value))

value = "ten"
print(type(value))

The first type is int and the second is str.

4. Mutable and immutable objects

A mutable object can be changed after it is created. Lists, dictionaries and sets are common mutable types.

An immutable object cannot be changed after creation. Integers, floats, strings and tuples are common immutable types.

This distinction matters when objects are shared between variables or passed to functions.

Type conversion changes a value from one type to another. Common conversion functions include int(), float(), str() and bool().

age_text = "19"
age_number = int(age_text)

price = 25
price_text = str(price)

Some conversions may fail. For example, int("hello") raises a ValueError because the text is not a valid integer representation.

Input from input() is returned as a string, so numeric input often needs conversion before arithmetic.

6. Operators in Python

Arithmetic operators: +, −, *, /, //, %, **.

  • / performs division and returns a floating-point result.
  • // performs floor division.
  • % returns the remainder.
  • ** performs exponentiation.

Comparison operators: ==, !=, >, <, >= and <=. They produce Boolean results.

Logical operators: and, or and not. They combine or reverse logical conditions.

Assignment operators: =, +=, −=, *= and others.

Membership operators: in and not in.

Identity operators: is and is not. They test whether two references point to the same object, not merely whether their values are equal.

7. Conditional statements

Conditional statements allow a program to choose which instructions to execute based on a condition.

marks = 72

if marks >= 90:
    print("Excellent")
elif marks >= 60:
    print("Good")
else:
    print("Needs improvement")

The if block runs when its condition is true. elif checks another condition if earlier conditions were false. else handles the remaining cases.

Python uses indentation to define code blocks. Incorrect indentation can cause an IndentationError or change the program's structure.

8. Nested conditions and compound conditions

A condition can contain another condition, called a nested if statement. Multiple conditions can also be combined using and, or and not.

age = 20
has_id = True

if age >= 18 and has_id:
    print("Condition satisfied")
else:
    print("Condition not satisfied")

Use parentheses when they make complex conditions easier to understand. Remember that and is true only when both conditions are true; or is true when at least one condition is true.

9. The for loop

A for loop iterates over the items of an iterable, such as a list, string, tuple or range.

for number in range(2, 6):
    print(number)

This prints 2, 3, 4 and 5. The stop value 6 is excluded.

The range(start, stop, step) form allows control over the starting value, stopping point and interval between values.

10. The while loop

A while loop repeats as long as its condition remains true.

count = 1

while count <= 5:
    print(count)
    count += 1

The counter is increased on every iteration. If the condition never becomes false and there is no exit, the loop may run indefinitely.

11. break, continue and pass
  • break: Immediately exits the nearest enclosing loop.
  • continue: Skips the remaining statements in the current iteration and moves to the next iteration.
  • pass: Does nothing; it acts as a placeholder where a statement is syntactically required.
12. Functions and parameters

A function is a reusable block of code that performs a task. Functions help divide a large program into smaller, understandable parts.

def calculate_area(length, width):
    area = length * width
    return area

result = calculate_area(5, 3)
print(result)

Here, length and width are parameters. The values 5 and 3 supplied during the call are arguments. return sends a result back to the caller.

A function that reaches the end without an explicit return statement returns None.

13. Types of function arguments
  • Positional: Values are assigned according to their order.
  • Keyword: Values are supplied using parameter names.
  • Default: A parameter has a predefined value if no argument is supplied for it.
  • Variable-length: *args collects additional positional arguments into a tuple; **kwargs collects additional keyword arguments into a dictionary.

    print(message, name)

14. Local and global scope

A variable created inside a function normally has local scope. It can be used within that function.

A variable defined at module level has global scope within that module. The global keyword allows a function to reassign a global name, while nonlocal is used to reassign a name in an enclosing function scope.

Prefer passing values through parameters and returning results rather than depending heavily on global variables. This makes programs easier to test and maintain.

15. Common programming errors
  • SyntaxError: The code does not follow Python's grammar.

Chapter 1: Algorithm Analysis and Complexity

What is an algorithm?

An algorithm is a finite sequence of precise instructions that solves a defined problem. A good algorithm should be correct, unambiguous, finite and efficient.

Why analyse algorithms?

Algorithm analysis estimates the resources required as input size increases. The main resources are execution time and memory usage.

Input size

Input size is represented by n. It may mean the number of elements in an array, characters in a string, vertices in a graph or another measure appropriate to the problem.

Asymptotic notations

  • Big O, O(g(n)): An asymptotic upper bound.
  • Big Omega, Ω(g(n)): An asymptotic lower bound.
  • Big Theta, Θ(g(n)): A tight asymptotic bound.

These notations describe growth rates while ignoring constant factors and lower-order terms.

Common complexity classes

  • O(1): Constant time.
  • O(log n): Logarithmic time.
  • O(n): Linear time.
  • O(n log n): Linearithmic time.
  • O(n²): Quadratic time.
  • O(2ⁿ): Exponential time.
  • O(n!): Factorial time.

Best, average and worst cases

Best case describes the minimum work for an input of a given size. Average case estimates expected work under an input distribution. Worst case describes the maximum work for that size.

Space complexity

Space complexity measures memory usage. Auxiliary space refers to the extra memory used by an algorithm, excluding the input storage when the analysis convention excludes it.

Chapter 5: Searching Algorithms

Searching

Searching is the process of locating a target value in a collection and determining its position or whether it exists.

Linear search

Linear search checks elements one by one until the target is found or the collection ends. It works on sorted and unsorted data.

Best-case time: O(1). Worst-case time: O(n). Auxiliary space: O(1) for an iterative implementation.

Binary search

Binary search repeatedly divides a sorted search interval into two halves. It compares the target with the middle element and continues in the relevant half.

Time complexity: O(log n). Iterative auxiliary space: O(1).

Important condition: The collection must be sorted according to the ordering used by the search.

Binary search procedure

  1. Set the left and right boundaries.
  2. Calculate the middle position.
  3. Compare the middle value with the target.
  4. If equal, return the position.
  5. If the target is smaller, continue in the left half; otherwise, continue in the right half.
  6. Stop when the search interval becomes empty.

Other search approaches

Hash-based lookup can provide expected O(1) access under suitable hashing assumptions. Tree-based searching depends on the tree structure and its balance.

Solution: Check 3, then 5, then 7. The target is at index 2 using zero-based indexing.

Worked example — Moderate

Question: In the sorted array [2, 4, 6, 8, 10, 12, 14], search for 12 using binary search.

Solution: The middle value is 8. Since 12 is larger, search the right half [10, 12, 14]. The middle of that interval is 12, so the target is found.

Chapter 6: Sorting Algorithms

Sorting

Sorting arranges elements according to an order, such as ascending or descending. It can make searching and data processing easier.

Bubble sort

Bubble sort repeatedly compares adjacent elements and swaps them when they are in the wrong order.

Average and worst-case time: O(n²). Optimised best case: O(n) when no swaps are needed in the first pass.

Selection sort

Selection sort repeatedly selects the smallest remaining element and places it in the next sorted position.

Best, average and worst-case time: O(n²). It generally performs O(n) swaps.

Insertion sort

Insertion sort builds a sorted portion by inserting each new element into its correct position.

Best-case time: O(n). Average and worst-case time: O(n²).

Merge sort

Merge sort divides the collection into smaller parts, sorts them recursively and merges the sorted parts.

Time complexity: O(n log n) in best, average and worst cases. Typical array implementations require O(n) auxiliary space.

Quick sort

Quick sort selects a pivot, partitions elements around it and recursively sorts the partitions.

Average time: O(n log n). Worst-case time: O(n²). Its practical performance depends on pivot selection and input arrangement.

Heap sort

Heap sort builds a heap and repeatedly removes the maximum or minimum element to form the sorted result.

Time complexity: O(n log n) in all cases, with O(1) auxiliary array space for an in-place implementation.

Chapter 7: Trees, Binary Search Trees and Heaps

Tree terminology

A tree is a hierarchical data structure consisting of nodes connected by edges. Important terms include root, parent, child, sibling, leaf, ancestor, descendant, depth and height.

Binary trees

A binary tree allows each node to have at most two children, conventionally called left and right.

Binary Search Tree

A Binary Search Tree (BST) follows an ordering property: values in the left subtree are smaller than the node's value, while values in the right subtree are larger, under the chosen duplicate-handling rule.

Search, insertion and deletion take O(h), where h is the tree height. A balanced tree has height O(log n); a highly skewed tree can have height O(n).

Tree traversals

  • Preorder: Root, left, right.
  • Inorder: Left, root, right.
  • Postorder: Left, right, root.
  • Level order: Visit nodes level by level.

Inorder traversal of a BST visits keys in sorted order.

Balanced search trees

AVL trees and Red-Black trees maintain balance conditions so that search, insertion and deletion can be performed in O(log n) time.

Heaps

A binary heap is a complete binary tree satisfying a heap-order property. In a max-heap, each parent is at least as large as its children. In a min-heap, each parent is no larger than its children.

Accessing the root takes O(1). Insertion and removal of the root take O(log n) in a binary heap.

Chapter 8: Hashing and Hash Tables

Hashing

Hashing maps a key to an index in a table using a hash function. It supports efficient lookup, insertion and deletion under suitable assumptions.

Hash functions

A hash function converts a key into a hash value or table index. A useful hash function distributes keys across the table to reduce collisions.

Collisions

A collision occurs when two different keys map to the same table location.

Collision resolution

  • Separate chaining: Store multiple entries in a collection at the same index.
  • Linear probing: Check successive table positions.
  • Quadratic probing: Check positions using quadratic offsets.
  • Double hashing: Use a second hash function to determine probe steps.

Load factor

The load factor α is the number of stored entries divided by the number of table slots:

\(\alpha=\frac{\text{Number of entries}}{\text{Table capacity}}\)

A high load factor can increase collisions and reduce performance.

Expected and worst-case complexity

Hash-table lookup, insertion and deletion are expected O(1) under suitable distribution and resizing assumptions. Worst-case performance can become O(n) if many keys collide.

Rehashing

When a table becomes too full, it may be resized and its entries inserted again using the new table capacity. This process is called rehashing.

Worked example

Solution: α = 12/20 = 0.6.

Chapter 9: Graph Algorithms and Traversal

Graph representation

Graphs can be stored using adjacency matrices or adjacency lists. An adjacency matrix uses O(V²) space, while an adjacency list uses O(V + E) space.

Breadth-First Search

Breadth-First Search (BFS) explores a graph level by level. It uses a queue and is useful for finding shortest paths in unweighted graphs.

Depth-First Search

Depth-First Search (DFS) explores as far as possible along a path before backtracking. It can be implemented using recursion or an explicit stack.

Traversal complexity

With an adjacency-list representation, BFS and DFS take O(V + E) time, where V is the number of vertices and E is the number of edges.

Shortest-path algorithms

  • BFS: Shortest paths in unweighted graphs.
  • Dijkstra: Single-source shortest paths with non-negative edge weights.
  • Bellman-Ford: Supports negative edge weights and can detect reachable negative-weight cycles.
  • Floyd-Warshall: All-pairs shortest paths, with O(V³) time in its standard form.

Minimum spanning trees

A minimum spanning tree connects every vertex of a connected, undirected, weighted graph with minimum total edge weight and no cycles.

  • Kruskal's algorithm: Sort edges by weight and add edges that do not form a cycle.
  • Prim's algorithm: Grow a tree by repeatedly adding a minimum-weight edge connecting the tree to an outside vertex.

Chapter 1: Operating System Fundamentals

1.1 Meaning and Purpose

An operating system (OS) is system software that manages computer hardware and provides services to application programs. It acts as an intermediary between users, applications and hardware. Examples include Windows, Linux, macOS, Android and iOS.

The OS manages processor time, main memory, files, storage devices, input/output devices, security and communication between processes.

1.2 Main Objectives

  • Convenience: makes the computer easier to use.
  • Efficiency: uses hardware resources effectively.
  • Resource management: allocates CPU, memory and devices.
  • Protection: controls access to resources.
  • Abstraction: provides simpler interfaces over complex hardware.

1.3 Types of Operating Systems

  • Batch OS: collects jobs and processes them in batches with limited direct user interaction.
  • Multiprogramming OS: keeps several jobs in memory so the CPU can work on another job when one waits for I/O.
  • Time-sharing OS: allocates short CPU time slices to interactive users or processes.
  • Multiprocessing OS: uses multiple processing units or cores.
  • Real-time OS: is designed to meet timing requirements. Hard real-time systems have strict deadlines; soft real-time systems tolerate occasional deadline misses.
  • Distributed OS: coordinates resources across multiple networked computers.
  • Embedded OS: operates within a dedicated device with specific requirements.

1.4 Kernel and Shell

The kernel is the central component of an operating system. It manages privileged operations such as scheduling, memory management, device access and system calls. A shell provides a user interface through which commands or other requests can be submitted.

A command-line shell accepts textual commands. A graphical shell provides windows, menus and icons.

1.5 Kernel Architectures

  • Monolithic kernel: many OS services operate within kernel space. This can offer efficient communication but creates a large privileged code base.
  • Microkernel: keeps the kernel relatively small and moves many services into user space. This can improve isolation but may introduce communication overhead.
  • Hybrid kernel: combines design ideas from monolithic and microkernel approaches.

1.6 System Calls

A system call is a controlled interface through which a user program requests a service from the kernel. Common categories include process control, file management, device management, information maintenance and communication.

Examples include creating a process, opening a file, reading data and allocating memory. The exact system-call names and interfaces differ between operating systems.

1.7 User Mode and Kernel Mode

Modern processors support privilege levels. User-mode programs have restricted access to hardware and protected resources. Kernel-mode code can execute privileged instructions. A system call or interrupt can transfer control to the kernel through a controlled mechanism.

1.8 Interrupts and Traps

An interrupt is an event that causes the processor to temporarily suspend its current execution and handle an event. Hardware interrupts commonly signal device events. A trap or exception is generally associated with an instruction or condition during program execution, such as an invalid operation or a system-call request.

Chapter 2: Processes and Threads

2.1 Program and Process

A program is a passive set of instructions stored on a device. A process is a program in execution, together with its current state and allocated resources. Multiple processes may execute instances of the same program.

2.2 Process Memory Layout

  • Text section: executable instructions.
  • Data section: global and static variables.
  • Heap: dynamically allocated memory.
  • Stack: function calls, local variables and return information.

2.3 Process Control Block (PCB)

The PCB is a kernel data structure containing information needed to manage a process. It commonly stores the process identifier, process state, program counter, CPU registers, scheduling information, memory-management information, accounting information and I/O status.

During a context switch, the OS saves the state of the current process and restores the state of the next process.

2.4 Process States

  • New: process is being created.
  • Ready: process can execute but is waiting for CPU allocation.
  • Running: process currently has the CPU.
  • Waiting/Blocked: process waits for an event, such as I/O completion.
  • Terminated: process has finished or has been stopped.

A running process may move to ready after pre-emption, to waiting after requesting I/O, or to terminated after completion.

2.5 Schedulers

  • Long-term scheduler: controls which jobs enter the system for processing.
  • Short-term scheduler: selects a ready process for CPU execution.
  • Medium-term scheduler: may suspend and later resume processes, often as part of swapping or memory-load management.

2.6 Context Switching

A context switch occurs when the CPU changes from one process or thread to another. The OS saves the old execution context and loads the new one. Context switching is necessary for multitasking but adds overhead because the CPU performs management work rather than useful application instructions.

2.7 Threads

A thread is a unit of CPU execution within a process. Threads in the same process commonly share code, data and open resources, while each thread has its own program counter, register state and stack.

Threads can improve responsiveness and allow concurrent work. However, shared data introduces synchronisation and race-condition concerns.

2.8 User-Level and Kernel-Level Threads

  • User-level threads: managed by a user-space thread library. Management may be fast, but some mapping models can limit parallelism or cause blocking complications.
  • Kernel-level threads: managed by the OS kernel. They can be scheduled independently by the kernel, though management involves kernel overhead.

2.9 Multithreading Models

The many-to-one model maps many user threads to one kernel thread. The one-to-one model maps each user thread to a kernel thread. The many-to-many model multiplexes user threads over a set of kernel threads. Their trade-offs concern parallelism, blocking behaviour and management overhead.

2.10 Inter-Process Communication (IPC)

Processes may communicate through shared memory or message passing. Shared memory allows processes to access a common region and requires suitable synchronisation. Message passing exchanges data through send and receive operations and can be direct or indirect through mailboxes.

Chapter 3: CPU Scheduling Algorithms

3.1 Purpose of CPU Scheduling

CPU scheduling selects a process from the ready queue for execution. The objective is to use the processor effectively while providing suitable response and waiting times.

3.2 Scheduling Criteria

  • CPU utilisation: percentage of time the CPU is busy.
  • Throughput: number of processes completed per unit time.
  • Turnaround time: completion time minus arrival time.
  • Waiting time: total time spent waiting in the ready queue.
  • Response time: first CPU response time minus arrival time.

For a process with arrival time AT, burst time BT and completion time CT:

Turnaround Time = CT − AT

Waiting Time = Turnaround Time − BT

Response Time = First Start Time − AT

3.3 Pre-emptive and Non-Pre-emptive Scheduling

In non-pre-emptive scheduling, a running process normally keeps the CPU until it finishes or blocks. In pre-emptive scheduling, the OS may interrupt a running process and assign the CPU to another process.

3.4 First Come First Served (FCFS)

FCFS schedules processes in order of arrival. It is simple and non-pre-emptive. However, a long process at the front of the queue can make many short processes wait. This is known as the convoy effect.

3.5 Shortest Job First (SJF)

SJF selects the ready process with the smallest next CPU burst. In its basic form it is non-pre-emptive. If burst lengths are known or estimated accurately, SJF minimises average waiting time for a set of processes under standard assumptions. Long jobs may experience starvation if short jobs continually arrive.

3.6 Shortest Remaining Time First (SRTF)

SRTF is the pre-emptive version of SJF. It selects the process with the least remaining CPU burst. A newly arriving process may pre-empt the currently running process if its remaining time is smaller.

3.7 Priority Scheduling

Priority scheduling selects the highest-priority ready process. It can be pre-emptive or non-pre-emptive. Low-priority processes may starve. Aging gradually increases the priority of waiting processes to reduce this problem.

3.8 Round Robin (RR)

Round Robin gives each ready process a fixed time quantum. If a process does not finish within the quantum, it is pre-empted and placed at the back of the ready queue.

A very large quantum makes RR resemble FCFS. A very small quantum increases context-switching overhead. Quantum selection therefore balances responsiveness and overhead.

3.9 Multilevel Queue and Multilevel Feedback Queue

Multilevel queue scheduling divides processes into separate queues, each potentially using a different scheduling policy. Processes may be permanently assigned to a queue. Multilevel feedback queue scheduling allows processes to move between queues according to their behaviour, CPU usage or waiting time.

3.10 Solved Example

Consider one process with arrival time 2, burst time 5 and completion time 11.

  • Turnaround time = 11 − 2 = 9 time units.
  • Waiting time = 9 − 5 = 4 time units.

If its first CPU start time was 4, its response time would be 4 − 2 = 2 time units.

Chapter 4: Process Synchronisation and Semaphores

4.1 Race Conditions

A race condition occurs when the outcome of concurrent operations depends on their timing or interleaving. If two threads update shared data without suitable coordination, the final result may be incorrect.

4.2 Critical Section Problem

A critical section is a part of a program that accesses shared data or resources. A correct solution should satisfy:

  • Mutual exclusion: at most one process is in the critical section for a protected resource at a time.
  • Progress: if no process is in the critical section and some wish to enter, selection should not be postponed indefinitely.
  • Bounded waiting: a process should not wait indefinitely after requesting entry while others repeatedly enter.

4.3 Mutex Locks

A mutex is a mutual-exclusion lock. A thread acquires the lock before accessing protected shared data and releases it afterward. The lock must be used consistently on every relevant execution path.

4.4 Semaphores

A semaphore is a synchronisation variable accessed through atomic operations. A counting semaphore can represent multiple available instances of a resource. A binary semaphore has two logical states and can be used for signalling or mutual exclusion, though a mutex has ownership semantics that a semaphore may not have.

  • wait (P): attempts to decrement the semaphore; if the resource is unavailable, the caller may block.
  • signal (V): increments the semaphore or wakes a waiting process, according to the implementation.

4.5 Producer-Consumer Problem

The producer creates items and places them in a shared bounded buffer. The consumer removes items. Synchronisation must prevent insertion into a full buffer, removal from an empty buffer and unsafe simultaneous access to the buffer structure.

A common conceptual solution uses a mutex for buffer access, an empty-count semaphore for available slots and a full-count semaphore for occupied slots.

4.6 Readers-Writers Problem

Readers access shared data without changing it, while writers modify it. Multiple readers may be allowed concurrently, but a writer generally requires exclusive access. Different policies may prioritise readers, writers or fairness.

4.7 Dining Philosophers Problem

The dining philosophers problem models processes competing for limited shared resources. Poor resource acquisition order can cause deadlock or starvation. General solutions include resource ordering, limiting simultaneous contenders or using a coordinator.

4.8 Monitors and Condition Variables

A monitor encapsulates shared data and operations that access it, ensuring controlled mutual exclusion. Condition variables allow threads to wait for a condition and be notified when it may have changed. A thread should normally re-check the condition after waking because notification alone does not guarantee the condition is true.

4.9 Busy Waiting and Blocking

Busy waiting repeatedly checks whether a condition has become true, consuming CPU time. Blocking places a waiting process into a sleep state so the CPU can execute other work. Spinlocks may be suitable for very short waits in certain kernel or multiprocessor contexts.

Chapter 5: Deadlocks

5.1 Meaning of Deadlock

A deadlock is a situation in which a set of processes cannot proceed because each process is waiting for a resource or event that another process in the set must release or produce.

5.2 Four Necessary Conditions

  • Mutual exclusion: at least one resource cannot be shared simultaneously.
  • Hold and wait: a process holds resources while requesting additional resources.
  • No pre-emption: resources cannot be forcibly taken away under the resource model.
  • Circular wait: a circular chain of processes exists, each waiting for a resource held by the next.

All four conditions are necessary for deadlock in the classic resource-allocation model. Breaking at least one prevents deadlock under that model.

5.3 Resource Allocation Graph

A resource-allocation graph contains process nodes and resource-type nodes. A request edge P → R indicates that a process requests a resource. An assignment edge R → P indicates that an instance has been allocated to a process.

With one instance per resource type, a cycle indicates deadlock. With multiple instances, a cycle indicates the possibility of deadlock but is not sufficient by itself to prove one.

5.4 Deadlock Prevention

Prevention ensures at least one necessary condition cannot hold. Examples include requiring processes to request all resources at once, imposing a global resource ordering or allowing pre-emption for suitable resources. These approaches can reduce resource utilisation or create other practical difficulties.

5.5 Deadlock Avoidance

Avoidance examines resource requests and grants them only if the resulting state remains safe. A safe state has an order in which all processes can obtain their remaining resources and complete. An unsafe state is not necessarily already deadlocked, but it may lead to deadlock.

5.6 Banker's Algorithm

The Banker's Algorithm uses the Available, Allocation, Max and Need structures. Need is calculated as:

Need = Max − Allocation

The safety test repeatedly finds an unfinished process whose Need is less than or equal to Work, initially set to Available. It then assumes that process finishes and releases its allocated resources back to Work. If all processes can finish, the state is safe.

5.7 Deadlock Detection

Detection allows deadlocks to occur and examines the resource-allocation state to identify them. For single-instance resources, a wait-for graph can be checked for cycles. Multiple-instance systems use more detailed detection algorithms based on current allocations and outstanding requests.

5.8 Recovery

Recovery may terminate all deadlocked processes, terminate selected processes one at a time, or pre-empt resources where safe. Victim selection may consider process priority, work completed, resources held and the cost of restarting. Repeatedly selecting the same process can cause starvation.

5.9 Deadlock, Starvation and Livelock

  • Deadlock: processes are blocked indefinitely while waiting for one another.
  • Starvation: a process waits indefinitely because resources or CPU time keep going to others.
  • Livelock: processes continue changing state in response to each other but make no useful progress.

Chapter 6: Memory Management and Allocation

6.1 Role of Memory Management

Memory management tracks which parts of main memory are in use, allocates memory to processes, protects address spaces and supports movement between logical and physical addresses.

6.2 Logical and Physical Addresses

A logical or virtual address is generated by the CPU from a process's point of view. A physical address identifies a location in main memory. The memory management unit (MMU) performs address translation using hardware-supported structures.

6.3 Contiguous Memory Allocation

In contiguous allocation, a process occupies a continuous region of physical memory. Fixed partitions divide memory into predefined regions. Variable partitions allocate regions based on process requirements.

  • Internal fragmentation: unused space inside an allocated block.
  • External fragmentation: free memory is split into separate holes, making a large contiguous allocation difficult even when total free space is sufficient.

6.4 Placement Strategies

  • First fit: selects the first sufficiently large free block.
  • Best fit: selects the smallest sufficiently large block.
  • Worst fit: selects the largest available block.
  • Next fit: continues searching from the location of the previous search.

The effectiveness of these strategies depends on the allocation pattern and workload; no strategy is universally best.

6.5 Compaction

Compaction moves allocated regions so that scattered free holes combine into a larger contiguous free region. It requires relocation support and can be expensive because data must be moved.

6.6 Paging

Paging divides a process's logical address space into fixed-size pages and physical memory into equal-size frames. Any page can be placed in any available frame. A page table maps virtual page numbers to physical frame numbers.

Paging eliminates external fragmentation in physical allocation, but the final page of a process may contain unused space, producing internal fragmentation.

6.7 Address Translation

A virtual address is commonly divided into a page number and an offset. The page number selects a page-table entry, which identifies a frame. The offset remains unchanged when forming the physical address.

Physical Address = Frame Number × Page Size + Offset

This expression assumes byte-addressable memory and that the offset is measured in bytes.

6.8 Page Table Structures

A single-level page table maps virtual pages to frames. Multilevel page tables divide the mapping into levels to avoid allocating a huge flat table for sparse address spaces. Hashed page tables and inverted page tables are alternative structures used in some systems.

6.9 Translation Lookaside Buffer (TLB)

A TLB is a small, fast cache of recent address translations. A TLB hit provides a translation without a full page-table walk. A TLB miss requires the system to consult the page table or perform a hardware-managed page-table walk.

6.10 Segmentation

Segmentation divides a program into logical variable-sized units such as code, data and stack. A logical address contains a segment identifier and offset. Segment tables contain base and limit information. Segmentation supports logical protection and sharing but can suffer from external fragmentation.

Chapter 7: Virtual Memory and Page Replacement

7.1 Virtual Memory

Virtual memory allows a process to use an address space that is larger or more convenient than the amount of physical memory currently allocated to it. Only the required portions need to be resident in main memory at a given time.

7.2 Demand Paging

In demand paging, a page is loaded into memory when it is first needed. If a process references a page that is not currently resident, a page fault occurs. The OS validates the reference, obtains a free frame or selects a victim page, loads the required page and resumes execution.

7.3 Page Fault Handling

  1. The hardware detects that the page is not present.
  2. Control transfers to the OS page-fault handler.
  3. The OS checks whether the address is valid and permitted.
  4. If valid, the OS locates the page on backing storage.
  5. A free frame is selected or a victim is replaced.
  6. If the victim is dirty, it may need to be written back.
  7. The required page is loaded and page-table information is updated.
  8. The interrupted instruction is restarted.

7.4 Page Replacement

When no free frame is available, a page-replacement algorithm chooses a page to remove. The goal is to reduce page faults while balancing overhead and implementation complexity.

7.5 FIFO

First-In First-Out replaces the page that has been in memory the longest. It is simple to implement, but it may remove a frequently used page. FIFO can exhibit Belady's anomaly, where increasing the number of frames increases the number of page faults for certain reference strings.

7.6 Optimal Page Replacement

The optimal algorithm replaces the page whose next use is farthest in the future. It gives the minimum possible number of page faults for a known reference string and fixed frame count. Since future references are not known in normal execution, it is mainly used as a theoretical benchmark.

7.7 Least Recently Used (LRU)

LRU replaces the page that has not been used for the longest time in the past. It uses recent history as a predictor of future use. Exact LRU may require hardware support or bookkeeping; practical systems often use approximations.

7.8 Second-Chance and Clock Algorithms

Second-Chance improves FIFO by using a reference bit. A page with its reference bit set receives another chance: the bit is cleared and the search continues. The Clock algorithm organises this idea in a circular structure with a moving pointer.

7.9 Thrashing

Thrashing occurs when the system spends excessive time handling page faults and moving pages rather than executing useful instructions. It can happen when processes collectively demand more frames than available memory can support efficiently.

7.10 Working Set and Page-Fault Frequency

The working set is an approximation of the pages a process has actively referenced during a recent window of execution. The working-set model helps estimate memory demand. Page-fault frequency control adjusts frame allocation based on observed fault rates.

7.11 Locality of Reference

  • Temporal locality: recently accessed instructions or data are likely to be accessed again.
  • Spatial locality: locations near recently accessed addresses are likely to be accessed.

Locality helps explain why caching, paging and hierarchical memory systems can perform effectively.

7.12 Effective Access Time

Effective access time depends on the probability of a TLB hit, page-table lookup cost, memory access cost and page-fault service time. Because page faults may involve storage I/O, even a small page-fault rate can have a large performance impact.

Chapter 8: File Systems, Disk Scheduling and I/O Management

8.1 File Concepts

A file is a named collection of related information stored on secondary storage. File metadata may include its name, type, size, location, ownership, permissions and timestamps.

8.2 File Operations

Common file operations include create, open, read, write, append, seek, close, rename and delete. The OS checks permissions and maintains information about open files.

8.3 Directory Structures

  • Single-level directory: all files share one directory.
  • Two-level directory: each user has a separate directory.
  • Tree-structured directory: directories may contain files and subdirectories.
  • Acyclic graph directory: sharing is allowed without directory cycles.
  • General graph directory: links may create cycles, requiring careful traversal and deletion rules.

8.4 File Allocation Methods

  • Contiguous allocation: file blocks occupy consecutive storage locations. It supports efficient sequential and direct access but can suffer from external fragmentation and file-growth difficulties.
  • Linked allocation: each block points to the next block. It supports easy growth but makes direct access inefficient and requires pointer storage.
  • Indexed allocation: an index structure stores pointers to a file's data blocks. It supports direct access but requires index storage.

8.5 Free-Space Management

File systems track unused blocks using methods such as bitmaps, linked free lists, grouping and counting. A bitmap uses one or more bits to represent block availability and can make it efficient to locate runs of free blocks.

8.6 File Protection

Protection mechanisms determine who can read, write, execute or modify files. Common approaches include permission bits, access-control lists and capability-based access. Authentication identifies a user; authorisation determines what that user is allowed to do.

8.7 Disk Structure and Access Time

Traditional magnetic disks contain rotating platters and tracks divided into sectors. Disk access time may include seek time, rotational latency and transfer time. Solid-state drives have no moving heads or rotational latency, so their performance characteristics differ.

8.8 Disk Scheduling Algorithms

  • FCFS: services requests in arrival order.
  • SSTF: selects the request closest to the current head position. It can reduce average seek distance but may starve distant requests.
  • SCAN: moves the disk head in one direction servicing requests, then reverses direction.
  • C-SCAN: services requests in one direction and returns to the beginning without servicing requests on the return movement.
  • LOOK: like SCAN but reverses at the last pending request in that direction rather than travelling to the physical end.
  • C-LOOK: like C-SCAN but jumps between the last and first pending requests.

8.9 I/O Management

The OS provides a uniform interface for devices through device drivers. Interrupt-driven I/O allows a device to notify the CPU when an event occurs. Polling repeatedly checks device status. Direct Memory Access (DMA) allows a controller to transfer blocks of data between a device and memory with limited CPU involvement after setup.

8.10 Buffering, Caching and Spooling

  • Buffering: temporarily holds data while it is transferred between components with different speeds or transfer sizes.
  • Caching: keeps copies of frequently or recently accessed data for faster access.
  • Spooling: queues jobs for a device that handles requests sequentially, such as a printer.

8.11 Protection and Security Basics

Operating systems use authentication, access control, process isolation, privilege separation, auditing and security updates to protect resources. The principle of least privilege means giving each user or process only the permissions necessary for its task.

Chapter 1: Number Systems and Binary Arithmetic

Number systems

A number system represents quantities using a defined set of symbols and a base (radix).

  • Binary: Base 2, digits 0 and 1.
  • Octal: Base 8, digits 0 through 7.
  • Decimal: Base 10, digits 0 through 9.
  • Hexadecimal: Base 16, digits 0 through 9 and A through F.

Positional representation

A number in base r is represented using powers of r. For example:

\((1011)_2=1(2^3)+0(2^2)+1(2^1)+1(2^0)=11_{10}\)

Binary arithmetic

Binary addition follows these rules: 0 + 0 = 0, 0 + 1 = 1, 1 + 0 = 1 and 1 + 1 = 10₂. A carry is passed to the next position when required.

Complements and signed numbers

The 1's complement is obtained by reversing every bit. The 2's complement is obtained by adding one to the 1's complement.

For an n-bit two's-complement representation, the signed range is −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.

Binary fractions

Digits after the binary point represent negative powers of two. For example, 0.101₂ = 1/2 + 0/4 + 1/8 = 0.625₁₀.

Question: Convert (1101)₂ into decimal.

Solution: 8 + 4 + 0 + 1 = 13.

Chapter 2: Boolean Algebra and Logic Gates

Boolean variables

Boolean algebra works with two values: 0 and 1. It is the mathematical foundation of digital circuits.

Basic operations

  • AND: Output is 1 only when both inputs are 1.
  • OR: Output is 1 when at least one input is 1.
  • NOT: Produces the complement of the input.

Universal gates

NAND is the complement of AND, while NOR is the complement of OR. Either NAND gates alone or NOR gates alone can be used to construct any Boolean function.

Exclusive gates

XOR produces 1 when its inputs differ. XNOR produces 1 when its inputs are equal.

Important Boolean laws

Identity: A + 0 = A; A · 1 = A.

Null: A + 1 = 1; A · 0 = 0.

Idempotent: A + A = A; A · A = A.

Complement: A + A̅ = 1; A · A̅ = 0.

De Morgan's laws: (A · B)̅ = A̅ + B̅ and (A + B)̅ = A̅ · B̅.

Truth tables

A truth table records the output of a logic expression for all possible input combinations. Two inputs require four rows; three inputs require eight rows.

Worked example

Question: Evaluate A AND B when A = 1 and B = 0.

Solution: 1 AND 0 = 0.

Worked example — Moderate

Question: Simplify A + A · B.

Solution: By the absorption law, A + A · B = A.

Chapter 3: Boolean Simplification and Karnaugh Maps

Why simplify Boolean expressions?

Simplification reduces the number of logic operations and can reduce circuit complexity, hardware cost, power consumption and propagation delay.

Sum of Products and Product of Sums

Sum of Products (SOP) is an OR combination of AND terms. Product of Sums (POS) is an AND combination of OR terms.

Minterms and maxterms

A minterm is an AND term containing every variable exactly once, complemented or uncomplemented. A maxterm is an OR term with the same variable coverage.

Karnaugh maps

A Karnaugh map is a visual method for simplifying Boolean functions. Adjacent cells differ in exactly one variable. Valid groups contain 1, 2, 4, 8 or another power-of-two number of cells.

Grouping rules

  • Use the largest valid groups possible.
  • Every required 1 must be covered for SOP simplification.
  • Groups may wrap around map edges.
  • Groups may overlap when this reduces the expression.
  • Don't-care conditions may be used when they help simplification.

Worked example

Question: Simplify F = A + A · B.

Solution: By absorption, F = A. The circuit needs only the input A.

Chapter 4: Combinational Logic Circuits

Combinational circuits

A combinational circuit produces outputs based only on its current inputs. It does not store previous input states.

Half adder

A half adder adds two binary bits:

Sum = A ⊕ B

Carry = A · B

Full adder

A full adder adds A, B and an input carry Cᵢₙ:

Sum = A ⊕ B ⊕ Cᵢₙ

Carry = AB + ACᵢₙ + BCᵢₙ

Multiplexers

A multiplexer selects one of several inputs and forwards it to a single output. A 2ⁿ-to-1 multiplexer requires n select lines.

Demultiplexers

A demultiplexer routes one input to one of several outputs based on select lines.

Encoders and decoders

An encoder converts an active input position into a coded output. A decoder converts a coded input into one of several output lines.

Comparators

A digital comparator determines whether one binary value is greater than, equal to or less than another.

Worked example

Question: A half adder receives A = 1 and B = 1. Find sum and carry.

Solution: Sum = 1 XOR 1 = 0. Carry = 1 AND 1 = 1.

Chapter 5: Sequential Circuits, Flip-Flops and Counters

Sequential circuits

A sequential circuit depends on current inputs as well as stored previous state. It contains memory elements.

Latches and flip-flops

A latch is generally level-sensitive, while a flip-flop is generally edge-triggered by a clock signal.

Common flip-flops

  • SR: Set-reset storage element.
  • JK: A modified SR design that handles the otherwise invalid input combination.
  • D: Stores the value present at its data input when triggered.
  • T: Toggles its state when enabled.

Registers

A register is a group of flip-flops used to store multiple bits. Shift registers move stored bits left or right and are used in serial data transfer and conversion.

Counters

A counter is a sequential circuit that moves through a defined sequence of states. An n-bit binary counter can represent up to 2ⁿ states.

Synchronous and asynchronous counters

In a synchronous counter, flip-flops share a common clock. In an asynchronous counter, the output of one stage can trigger the next stage.

Worked example

Question: How many states can a 4-bit binary counter represent?

Solution: 2⁴ = 16 states.

Practice questions

  1. Which circuit type stores previous state?
  2. Which flip-flop is commonly used for one-bit data storage?
  3. How many states can a 5-bit counter represent?
  4. What is the main difference between synchronous and asynchronous counters?
Reveal answers

1. Sequential circuit. 2. D flip-flop. 3. 32. 4. Whether the flip-flops share a common clock or are triggered in a chain.

Chapter 1: Basic Computer Organisation and Functional Units

Computer organisation

Computer organisation describes how hardware components are connected and how they operate together to execute programs.

Major functional units

  • Input unit: Accepts data and instructions.
  • Memory unit: Stores programs, data and intermediate results.
  • Arithmetic Logic Unit (ALU): Performs arithmetic and logical operations.
  • Control unit: Coordinates instruction execution and hardware operations.
  • Output unit: Presents processed results.

Central Processing Unit

The CPU contains processing and control components. Registers provide very fast storage for values required during instruction execution.

System buses

  • Data bus: Carries data between components.
  • Address bus: Carries addresses identifying locations or devices.
  • Control bus: Carries signals that coordinate operations.

Stored-program concept

In a stored-program computer, instructions and data are stored in memory. The CPU fetches instructions and executes them in sequence, subject to control-flow instructions.

Von Neumann and Harvard architectures

Von Neumann architecture generally uses a shared memory system for instructions and data. Harvard architecture uses separate instruction and data memories, potentially allowing simultaneous access.

Worked example

Question: Which CPU unit performs addition and logical comparisons?

Solution: The Arithmetic Logic Unit.

Practice questions

  1. Which unit coordinates computer operations?
  2. Which bus carries memory addresses?
  3. What is the main purpose of CPU registers?
  4. Which architecture uses separate instruction and data memories?
Reveal answers

1. Control unit. 2. Address bus. 3. Fast temporary storage. 4. Harvard architecture.

Chapter 2: CPU Registers and Instruction Execution

Important CPU registers

  • Program Counter (PC): Holds the address of the next instruction to fetch.
  • Instruction Register (IR): Holds the instruction currently being processed.
  • Memory Address Register (MAR): Holds a memory address for an access.
  • Memory Data Register (MDR): Holds data being transferred to or from memory.
  • Accumulator: Stores intermediate arithmetic or logical results in architectures that use it.

Instruction cycle

The basic instruction cycle contains three broad stages:

  1. Fetch: Retrieve the next instruction from memory.
  2. Decode: Interpret the operation and identify required operands.
  3. Execute: Perform the operation and update the required state.

Instruction formats

An instruction may contain an opcode and operand fields. The opcode identifies the operation, while operands identify data or locations used by that operation.

Addressing modes

  • Immediate: The operand value is part of the instruction.
  • Register: The operand is held in a CPU register.
  • Direct: The instruction specifies the memory address.
  • Indirect: The specified location or register provides the effective address.
  • Indexed: An index value contributes to the effective address.

Clock and performance

Clock frequency indicates the number of clock cycles per second. It does not alone determine processor performance, which also depends on instruction count, cycles per instruction, memory behaviour and architecture.

\(CPU\ Time=Instruction\ Count\times CPI\times Clock\ Cycle\ Time\)

Worked example

Question: A processor executes 1,000 instructions with an average CPI of 2. Find the total number of clock cycles.

Solution: 1,000 × 2 = 2,000 cycles.

  1. Which register holds the next instruction address?
  2. What are the three basic instruction-cycle stages?
  3. Which addressing mode stores the operand in the instruction itself?
  4. What does CPI mean?
Reveal answers

1. Program Counter. 2. Fetch, decode and execute. 3. Immediate. 4. Cycles Per Instruction.

Chapter 3: Memory Hierarchy and Cache Memory

Memory hierarchy

Computer systems organise storage into levels based on speed, capacity and cost. Faster storage is generally smaller and more expensive per bit.

A typical hierarchy is registers, cache, main memory and secondary storage.

Primary and secondary memory

RAM is volatile working memory. ROM and related non-volatile memory retain information without continuous power. Secondary storage includes SSDs and hard disk drives.

Cache memory

Cache stores copies of frequently or recently accessed data so that the CPU can access them faster than if every request went to main memory.

Locality of reference

  • Temporal locality: Recently accessed information is likely to be accessed again.
  • Spatial locality: Nearby memory locations are likely to be accessed.

Cache hit and miss

A cache hit occurs when requested data is present in cache. A cache miss occurs when it is absent and must be retrieved from another memory level.

Average memory access time

For a simple one-level cache model:

AMAT = Hit time + Miss rate × Miss penalty.

Cache mapping

  • Direct mapping: Each memory block maps to one specific cache line.
  • Fully associative: A block can occupy any cache line.
  • Set associative: A block maps to a set and can occupy any line within that set.

Worked example

Question: Cache hit time is 2 ns, miss rate is 0.1 and miss penalty is 50 ns. Find AMAT.

Solution: AMAT = 2 + (0.1 × 50) = 7 ns.

Practice questions

  1. Which is generally faster: cache or RAM?
  2. What is temporal locality?
  3. What is a cache miss?
  4. Find AMAT for hit time 1 ns, miss rate 0.2 and miss penalty 20 ns.
Reveal answers

1. Cache. 2. Reuse of recently accessed data. 3. Requested data is not present in cache. 4. 5 ns.

Chapter 4: Input/Output Organisation and Interrupts

Input/output organisation

I/O organisation manages communication between the CPU, memory and peripheral devices such as keyboards, displays, storage devices and network interfaces.

Programmed I/O

The CPU repeatedly checks device status and performs data transfers. This method can keep the CPU occupied while waiting for slower devices.

Interrupt-driven I/O

A device generates an interrupt when it needs attention. The CPU temporarily suspends its current execution, services the interrupt and then resumes the previous work when appropriate.

Direct Memory Access

DMA allows a controller to transfer blocks of data between an I/O device and memory with reduced continuous CPU involvement.

Interrupt handling

An interrupt service routine (ISR) is the code executed to handle an interrupt. The system preserves the necessary processor state so normal execution can continue afterward.

Polling and interrupts

Polling checks device status repeatedly. Interrupts allow a device to signal when service is needed. The appropriate method depends on system design and workload.

Worked example

Question: Which technique is useful for transferring a large block of data between a device and memory while reducing CPU involvement?

Solution: Direct Memory Access.

Practice questions

  1. What does an ISR do?
  2. What is the main idea behind polling?
  3. Which method allows device-to-memory transfers with reduced CPU involvement?
  4. Why are interrupts useful?
Reveal answers

1. Handles a particular interrupt. 2. Repeatedly checks device status. 3. DMA. 4. Devices can request CPU attention without continuous polling.
